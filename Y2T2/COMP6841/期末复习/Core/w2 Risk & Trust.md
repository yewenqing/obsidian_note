这份讲义是新南威尔士大学（UNSW）2026年第二学期 **COMP6441 / COMP6841 / LAWS3040 / CRIM3040** 的 **第 2 周核心大课课件（Week 2 Core Lecture）**，主题为 **《秘密与风险》（Secrets and Risks）**，主讲人为 Rahat Masood。

  

本周讲义的核心目标是帮助学生理解**什么是秘密、秘密为何及如何泄露、古典与现代隐藏信息的方式，以及如何科学地评估与应对风险**。以下是讲义的详细梳理与结构化解析：

  

### 一、 核心学习目标（Key Learning Outcomes）

讲义围绕 6 大核心问题展开：

  

1. **秘密的本质**：什么构成了一个秘密？
    
      
    
2. **隐藏信息的不同方式**：代码（Code）、密码/密码系统（Cipher）、加密（Encryption）与隐写术（Steganography）的区别。
    
      
    
3. **柯克霍夫原则（Kerckhoffs' Principles）**：为什么密钥的保密性远比算法保密更重要？
    
      
    
4. **秘密的泄露途径**：人、系统与行为模式。
    
      
    
5. **风险推理**：如何利用可能性（Likelihood）**与**影响程度（Impact）对风险进行建模与量化。
    
      
    
6. **判定偏差**：安全系统中的假阳性（误报）与假阴性（漏报）。
    
      
    

### 二、 安全演进与历史案例（Evolution of Security）

讲义从历史与哲学的角度回顾了人类对“安全”的构建过程：

  

- **史前时期（动物本能，公元前 10,000 年前）**：基于生物本能的“战或逃”（Fight, flight, or freeze）、寻找洞穴庇护与躲避捕食者。
    
      
    
- **早期人类社会（部落安全，公元前 10,000–3,000 年）**：通过建立部落/家族协作防御、出现分工（猎人、守卫、领袖）与群体规范。
    
      
    
- **古代文明（通信与政治安全，公元前 3,000–公元 500 年）**：战争与政治中开始运用隐写术与密码学，出现秘密使者与受保护的卷轴。
    
      
    - _历史案例 1（隐写术）_：古希腊人将信息刺青在奴隶剃光的头皮上，待头发重新长出后再派其送信。
        
          
        
    - _历史案例 2（两军问题 The Two Generals' Problem）_：经典思想实验，揭示在不可靠的通信信道上无法达成百分之百同步和“共同知识”（Common Knowledge）的状态。
        
          
        
- **古典与中世纪（制度与实体安全，公元 500–1500 年）**：成文法典、城堡/护城河/城墙等物理屏障，以及成建制的军队与法律机构。
    
      
    
- **现代安全映射**：过去的物理城堡、城墙与护城河，在现代数字世界中映射为防火墙（Firewall）、局域网（LAN）与广域网（WAN）的隔离。
    
      
    

### 三、 威胁主体（Who Are We Defending Against?）

讲义分析了 5 类动机与手段各不相同的攻击者：

  

1. **网络犯罪分子（Cybercriminals）**：以经济利益为目的（钓鱼、勒索软件、诈骗）。
    
      
    
2. **内部人员（Insiders）**：滥用合法权限（数据窃取、蓄意破坏、无意疏忽或失误）。
    
      
    
3. **国家级黑客（Nation-State Actors）**：间谍活动与地缘政治破坏（高级持续性威胁 APT、特种恶意软件）。
    
      
    
4. **黑客主义者（Hacktivists）**：出于政治或社会诉求（DDoS 攻击、网站涂鸦、数据泄露曝光）。
    
      
    
5. **商业竞争对手（Competitors）**：追求商业优势（商业间谍、知识产权 IP 窃取、非法监视）。
    
      
    

### 四、 秘密的定义与安全模型（CIA / CIANA）

1. **什么是秘密（What is a Secret?）**：秘密是**被故意对他人隐瞒以保护其价值或含义的信息**。被分享秘密意味着获得了信任，同时也承担了作为“内部人”的责任与攻击面风险。
    
      
    
2. **现代秘密的形态**：包括密码/Passkeys、API 密钥、私信、医疗健康记录、位置轨迹、学生成绩、未发表的研究、生物识别特征模板，以及 AI 提示词和上传的私有文件等。
    
      
    
3. **安全三要素（CIA Triad）**：
    
      
    - **机密性（Confidentiality）**：仅授权人员可读取。
        
          
        
    - **完整性（Integrity）**：确保数据准确、未被未经授权地篡改。
        
          
        
    - **可用性（Availability）**：确保系统与数据在需要时能正常访问。
        
          
        
4. **扩展模型（CIANA）**：
    
      
    - 在 CIA 基础上增加了 **不可否认性（Non-repudiation）**（发送方无法否认自身操作/签名）与 **身份认证（Authentication）**（核实用户与系统的真实身份）。
        
          
        
    - _在线考试平台案例_：泄题属于机密性失效；改分属于完整性失效；他人代考属于身份认证失效；考试期间系统崩溃属于可用性失效；学生否认交卷属于不可否认性失效。
        
          
        

### 五、 隐藏信息的技术与经典密码学

讲义辨析了 4 种隐藏或保护信息的手段：

  

- **代码（Code）**：在**单词/短语层面**替换含义（如用“The eagle has landed”代表“包裹已送达”；二战时期的纳瓦霍密码译员 Navajo Code Talkers）。
    
      
    
- **密码/密码系统（Cipher）**：使用特定规则或数学变换逐个替换或置换**字母/字符符号**（如 Caesar 密码、AES）。
    
      
    
- **加密（Encryption）**：结合算法与密钥来保护现代数字数据（如 HTTPS、端到端加密通信）。
    
      
    
- **隐写术（Steganography）**：**隐藏信息本身的存在**（如把机密文本藏在图片像素中）。
    
      
    

#### 1. 柯克霍夫原则（Kerckhoffs' Principles, 1883）与密钥管理

- **核心原则**：系统的安全性**不能依赖于算法的保密**，而必须**完全建立在密钥的保密性之上**（即便系统公开，只要密钥安全，系统就应是不可破解的）。
    
      
    
- **密钥管理的痛点（Key Management）**：现实中加密失效往往不是数学算法被攻破，而是密钥管理不当（如：将 API 密钥硬编码到代码中、把包含密钥的 `.env` 提交到 GitHub、密钥与密文存放在一起、泄露后未及时轮换等）。
    
      
    

#### 2. 古典密码的两大基石

- **置换密码 / 替换密码（Substitution Ciphers）**：位置不变，改变符号（如 Caesar 密码、ROT13）。
    
      
    - _缺陷_：单表替换会**保留明文的统计特征与字母重复模式**（Repeated letters stay repeated），极易通过词频分析破解。
        
          
        
- **移位密码 / 排列密码（Permutation / Transposition Ciphers）**：符号不变，改变位置（如栅栏密码 Rail Fence Cipher、列置换密码）。
    
      
    

### 六、 风险分析与管理（Risk Management）

讲义给出了安全工程中最经典的风险定义公式与评估框架：

  

$$\text{风险（Risk）} = \text{可能性（Likelihood）} \times \text{影响程度（Impact）}$$

当威胁（Threat）利用了系统漏洞（Vulnerability）并危及资产（Asset）时，便产生了风险。

  

#### 1. 风险矩阵（Likelihood vs Impact Matrix）

- 风险级别由发生概率（1 罕见到 5 极可能）与危害严重程度（1 微小到 5 灾难性）共同决定。
    
      
    
- **低概率、高影响事件（Low Likelihood, High Impact Events）**：发生概率极低但一旦发生将带来灾难性后果（如助教电脑无密码且无备份丢失学生成绩、勒索病毒瘫痪全校、云配置错误导致大规模数据泄露、APT 国家级攻击、自然灾害等）。
    
      
    

#### 2. 风险分析与处置 5 步流程

1. **资产（Assets）**：我们要保护什么？
    
      
    
2. **威胁（Threats）**：什么可能造成破坏？
    
      
    
3. **漏洞（Vulnerabilities）**：我们的薄弱点在哪里？
    
      
    
4. **风险评估（Risk Assessment）**：计算其可能性与影响。
    
      
    
5. **风险处置（Risk Treatment）**：选择合适应对方案。
    
      
    

#### 3. 风险处置的 6 种策略（Stages of Resolving Risk）

- **规避（Avoid）**：停止导致风险的活动。
    
      
    
- **降低/缓解可能性（Mitigate Likelihood）**：通过培训、报警等措施降低发生概率。
    
      
    
- **降低/缓解影响（Mitigate Impact）**：通过灭火设施、数据备份等降低事故后果。
    
      
    
- **转移（Transfer）**：通过外包、合同或保险将风险转给第三方。
    
      
    
- **共担/汇聚（Pooling）**：在多个主体间分摊风险（如多元化投资）。
    
      
    
- **受险/接受（Accept）**：了解并接受风险（通常适用于低概率低影响事件）。
    
      
    
- **免疫/弹性（Immunisation / Resilience）**：建立容灾与灾难恢复（Disaster Recovery）能力。
    
      
    

#### 4. 组织的风险边界

- **风险胃口（Risk Appetite）**：组织为实现目标**愿意主动承担**的风险水平。
    
      
    
- **风险承受能力（Risk Capacity）**：组织在不危及自身生存的前提下**能够承受的最大极限**风险。
    
      
    
- **风险容忍度（Risk Tolerance）**：在风险胃口范围内允许的偏离或波动程度。
    
      
    

### 七、 决策判定偏差：第一型与第二型错误（Type I and Type II Errors）

在不确定与带噪声的信息环境下，安全系统不可避免地会出现判定偏差：

  

|**实际情况**|**系统判定为“有威胁”（报警/采取行动）**|**系统判定为“无威胁”（放行/不采取行动）**|
|---|---|---|
|**实际无威胁（Innocent / Safe）**|**Type I Error（第一型错误 / 假阳性 / 误报 False Positive）**|正确放行（Correct Rejection）|
|**实际有威胁（Guilty / Threat）**|正确检测（Correct Detection）|**Type II Error（第二型错误 / 假阴性 / 漏报 False Negative）**|

- **网络安全中的典型权衡**：
    
      
    - **垃圾邮件过滤器**：误将正常邮件归入垃圾箱（Type I，影响效率） vs 钓鱼邮件漏进收件箱（Type II，面临安全风险）。
        
          
        
    - **杀毒软件 / EDR**：误杀安全文件（Type I，导致业务中断） vs 漏报恶意木马（Type II，导致系统沦陷）。
        
          
        
    - **钓鱼告警**：误报正常网站（Type I，降低用户信任度） vs 漏报钓鱼链接（Type II，导致凭证被盗）。
        
          
        
- **核心启示**：过度抑制一种错误往往会导致另一种错误急剧上升，安全工程的精髓在于**根据资产价值与业务场景在误报与漏报之间取得合理平衡**。
