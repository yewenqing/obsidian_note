## 二、 安全的演进历程 (Evolution of Security)

安全的概念随着人类文明的发展而演进，紧随人类最基础的生理需求之后：

1. **生物学生存时代**：人类居住在洞穴/树下，安全处于动物本能阶段。
    
2. **部落时代 (10,000 BCE - 3,000 BCE)**：人类开始群居，演化出专门的分工（**守卫**负责物理安全、**领袖**解决冲突、**猎人**获取食物）。
    
3. **古代文明时代**：人类开始建立领土，因利益和土地所有权产生冲突。为赢得战争，开始出现**秘密信息、编码符号和受保护的手稿**，这也是**隐写术**与早期密码学的萌芽。
    
4. **中世纪时代**：安全变得更加精致，建立了城堡和堡垒以保护核心资产（国王/领袖/财富），并引入了法律（源自罗马法）。
    

## 三、 网络安全三大基本原则：CIA 三要素

网络安全的核心由以下三大支柱构成（现代安全已扩展为 **SIENA** 五要素）：

|**原则**|**定义**|**历史/现代案例**|
|---|---|---|
|**机密性 (Confidentiality)**|确保信息**仅能**被授权用户访问。|历史：隐写术、加密、物理城墙。<br><br>  <br><br>现代：HTTPS、密码管理器。|
|**完整性 (Integrity)**|确保数据是准确的，且在传输或存储中**未被篡改**。|**两个将军问题**中信息被篡改或传错。网络安全要求发送与接收的数据完全一致。|
|**可用性 (Availability)**|确保系统、数据和功能在**需要时可被正常访问**。|历史：受高性能计算(HPC)限制较大。<br><br>  <br><br>现代：**DDoS 攻击**或**勒索软件**会导致可用性丧失（系统崩溃/数据被锁）。|

### 扩展：SIENA 原则

在 **CIA** 的基础上，现代安全增加了两个重要维度：

- **身份验证 (Authentication)**：在访问系统前验证身份。基于三个维度：_你拥有的东西_（如令牌）、_你是谁_（如生物特征）和_你知晓的东西_（如密码）。
    
- **不可否认性 (Non-repudiation)**：确保发送方**无法否认**其发送过的信息或签名（防止事后抵赖）。
    

## 四、 保护信息与隐藏秘密的四种机制

> **秘密的定义**：为了保护其价值或意义，而被故意隐瞒不让其他人知晓的信息。

1. **编码 (Code)**：用其他词汇或数字**替换整个词组或短语**，隐藏的是**含义 (Meaning)**。（例：“老鹰已降落” 替换 “包裹已送达”；二战纳瓦霍密码译员）。
    
2. **密码 (Cipher)**：利用算法**打乱字母顺序或改变字母形式**（例：**凯撒密码/移位密码**，$Key=3$ 时 A ➡️ D）。
    
3. **加密 (Encryption)**：结合密钥 (Key)和数学算法来保护数字数据（例：HTTPS、加密聊天）。
    
4. **隐写术 (Steganography)**：隐藏**信息存在的事实 (Existence)**。（例：古代剃光头刻字；现代在 PNG/JPEG 图片属性的 Description 中藏匿明文）。
    

> ⚠️ **秘密泄露的三大渠道**：**人员**（焦虑/大意/过度热情）、**行为模式**（网络数据包的时间、流量可预测性规律）、**系统**（日志残留/漏洞）。

## 五、 柯克霍夫原则与密钥管理

- **柯克霍夫原则 (Kerckhoffs's Principle)**：加密系统的安全性不应取决于算法的保密，而应当**取决于密钥 (Key) 的保密**。算法（如 AES）应当对公众完全透明。
    
- **密钥管理的常见漏洞 (人是最大漏洞)**：
    
    - 在代码中**硬编码 API 密钥**（部署到生产环境时忘记删除）。
        
    - 在团队内**共享密码**。
        
    - 将密码或密钥**截图**保存，或写在物理**便利贴**上。
        
    - 密钥泄露后**未进行轮转/更改 (No Rotation)**。
        
    - 将包含敏感环境配置的文件无意上传至 **GitHub**。
        

## 六、 古典密码的分类与缺陷

- **置换/替换密码 (Substitution Cipher)**：改变符号，但**保留结构图案**（例：凯撒密码、ROT13、Pigeon密码）。
    
    - 缺陷：**不改变原句的模式和长度**。在长段落中，可以通过**频率分析**（如英文中 E、T、A 出现频率最高）轻松破译。
        
- **换位/排列密码 (Permutation/Transposition Cipher)**：不改变字母本身，但**打乱它们的位置/顺序**（例：**栅栏密码 Rail Fence Cipher**，通过矩阵zigzag书写再按行读取）。
    

## 七、 风险管理 (Risk Management)

$$\text{风险 (Risk)} = \text{可能性 (Likelihood)} \times \text{影响 (Impact)}$$

- **核心步骤**：识别资产 ➡️ 识别威胁 ➡️ 识别漏洞 ➡️ 风险矩阵评估 ➡️ 风险处置。
    
- **低可能性、高影响事件**（如：校园枪击、海啸、国家级黑客 APT 攻击、勒索软件）同样需要极高的安全关注。
    
- **考量维度**：在处置风险前，企业需明确自身的 **风险胃口 (Risk Appetite)**、**风险容量 (Risk Capacity)** 和 **风险耐受度 (Risk Tolerance)**。
    

## 八、 第一类错误与第二类错误 (核心考点)

|**错误类型**|**别名**|**网络安全定义 (以人脸识别/IDS为例)**|**物理世界类比**|
|---|---|---|---|
|**第一类错误 (Type 1)**|**伪阳性 (False Positive) / 误报**|拒绝**合法/无辜用户**的正常访问请求（系统太严苛）。|冤枉好人；将正常邮件拦截进垃圾箱。|
|**第二类错误 (Type 2)**|**伪阴性 (False Negative) / 漏报**|允许**恶意/未经授权**的黑客进入系统（安全有漏洞）。|放走坏人；将恶意木马文件放行入内网。|

- **设计原则**：在网络安全系统中，两类错误此消彼长。**无法做到 100% 消除两者**，必须根据安全需求和用户体验在两者之间**寻找平衡点 (Balance)**。
