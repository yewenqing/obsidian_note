
### 📝 报告素材：实验环境搭建与协议边界对抗实例

#### 1. 实验现象描述

在构建基于 MITM（中间人）架构的数据包监听环境时，测试客户端（版本 1.20+）通过本地代理端口（`127.0.0.1:25555`）尝试接入本地搭建的 PaperMC 服务端（`127.0.0.1:25565`）。客户端界面随后弹出 `Connection Reset`（连接重置）错误，连接强行终止。

#### 2. 代理层异常日志捕获与分析

通过查阅中间人代理工具（SniffCraft）的控制台流式日志，捕获到了在会话握手阶段的关键错误：

Plaintext

```
[Handshake] [C --> (SC)] Client Intention
[Login] [C --> S] Hello
WARNING, trying to connect to a server with encryption enabled
but impossible without being authenticated.
Exception when reading the data: Not authenticated
```

**根据网络协议栈与 Minecraft 官方认证流（Authentication Flow）分析，该异常的深层触发机理如下：**

- **握手与意图宣告**：客户端首先向代理发送 `Client Intention` 数据包，表明连接意图；随后代理将其转发，并由客户端发送 `Hello`（即登录启动包，包含玩家 ID 等基本信息）。
    
- **信任边界的密文升级**：由于服务端默认开启了正版验证（`online-mode=true`），为了防止中间人监听和重放攻击，服务端会生成一个临时的 AES 对称密钥，并使用 Mojang 官方的 RSA 公钥进行加密传输，要求客户端必须开启**全流量密文通信**。
    
- **认证断层与连接崩溃**：在此阶段，由于中间人代理软件（SniffCraft）本身并未通过微软会话服务器（Session Server）的 OAuth2.0 令牌（Token）认证，其无法获取解密所需的动态会话密钥，导致其网络层（Netty 框架底层）在尝试读取后续压缩/加密的明文数据时抛出 `Not authenticated` 异常。为了防止协议状态机崩溃，代理端的主动防御机制直接向 TCP 链路发送了 `RST` 报文，从而在客户端引发了 `Connection Reset` 现象。
    

#### 3. 边界防御的消解方案（实验验证）

为了在实验环境下绕过复杂的公网正版 Token 刷新机制，使数据包能够以明文（Plaintext）形式暴露以供后续的反作弊机制研究，本实验采取了“信任边界内移”的优化策略：

- 将服务端 `server.properties` 中的安全策略调整为 `online-mode=false`，切断与 Mojang 验证服务器的强绑定。
    
- 此举成功消解了握手阶段的强制 AES 加密协商，使得游戏数据包在经过代理网关时保持可读的结构化状态，成功为后续的移动（Fly）与战斗（KillAura）数据包特征分析扫清了障碍。
