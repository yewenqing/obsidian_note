# 1. 什么是 Security Engineering

讲义强调：

> 安全工程师不是“黑客”，而是工程师。

普通工程师：

- 修桥
    
- 造飞机
    
- 医疗设备
    

安全工程师：

- 设计能够抵御攻击的系统
    
- 解决数字世界中的风险问题
    

课程给出的定义：

> Security Engineering is about designing systems that remain safe even when humans, data, software, and AI are under attack.

即：

**即使人、数据、软件、AI 都受到攻击，系统依然能够安全运行。**

---

## 安全工程师关注什么

课程特别强调：

安全工程师不仅关注代码。

还要考虑：

- 用户行为
    
- 隐私
    
- 成本
    
- 可用性
    
- 恢复能力
    

这是一个重要思想：

### 安全 ≠ 把漏洞修掉

而是：

### 安全 = 风险管理

例如：

银行 App：

- 登录太简单 → 不安全
    
- 登录太复杂 → 用户跑了
    

所以必须平衡：

- Security
    
- Usability
    
- Cost

# 3. Bugs、Vulnerabilities、Exploitation

这是 Week1 最重要的概念之一。

讲义明确区分：

### Bug

程序错误。

例如：

- Null Pointer
    
- Buffer Overflow
    
- Race Condition
    

---

### Vulnerability

能够导致安全问题的 Bug。

例如：

- SQL Injection
    
- XSS
    
- Directory Traversal
    

---

### Exploitation

攻击者利用漏洞。

例如：

- RCE
    
- Privilege Escalation
    
- Session Hijacking
    

---

经典关系：

```text
Bug
 ↓
Vulnerability
 ↓
Exploitation
```

例如：

```text
输入校验错误
 ↓
SQL Injection
 ↓
数据库被窃取
```

# 6. Security by Design

这是整个课程最重要的工程思想。

课程引用 NIST：

> 在设计阶段就考虑安全。

---

原因：

修漏洞成本：

```text
设计阶段      1x
开发阶段      10x
上线后       100x
```

（经典软件工程规律）

所以：

### Security by Design

比

### Security after Incident

便宜得多。

```text

```

攻击者：

```text

```

---

因此：

安全工程本质是：

```text

```

而不是：

```text

```

# 二、SQL Injection Lecture

第二份讲义是：

> 用 SQL Injection 作为案例说明“数据与控制混淆”为什么危险。

---

# 核心思想

课程反复强调：

## Data 和 Control 必须分离

---

例如：

### Data

- 用户名
    
- 密码
    
- 语音
    

---

### Control

- SQL语句
    
- 程序命令
    
- 协议控制字段
    

---

如果两者混在一起：

就会产生：

```text
Injection Vulnerabilities
```

---

# 什么是 SQL Injection

本质：

用户输入本来应该是：

```text
Data
```

结果被数据库解释成：

```text
Control
```

---

例如：

程序员写：

```sql
SELECT *
FROM users
WHERE username = '用户输入'
```

如果把用户输入直接拼接：

```sql
SELECT *
FROM users
WHERE username = 'xxx'
```

数据库无法区分：

```text
哪些是数据
哪些是SQL命令
```

这就是 SQL Injection 的根源。

---

# 数据库基础

讲义快速复习：

SQL 常见命令：

```sql
SELECT
INSERT
UPDATE
DELETE
JOIN
UNION
WHERE
LIMIT
```

考试通常不会考语法细节。

重点是理解：

数据库执行的是：

```text
控制语句
```

而用户输入应该只是：

```text
数据
```

---

# SQL Injection 能造成什么

课程指出：

可能导致：

```text
读取数据库
```

```text
获取表结构
```

```text
获取敏感信息
```

---

讲义还提到：

Injection 不只是 SQLI。

同类问题还有：

- XSS
    
- Template Injection
    
- Buffer Overflow
    
- RCE
    

---

共同根源：

```text
Data 被当成 Control
```

---

# 如何防御 SQL Injection

讲义给出三个层次：

### 1. Blacklist

禁止字符。

例如：

```text
禁止 '
禁止 ;
```

课程评价：

```text
Never works
```

因为绕过方法太多。

---

### 2. WAF

Web Application Firewall

有用：

但不完美。

---

### 3. Prepared Statements

课程称为：

> Gold Standard

核心思想：

数据库预先确定：

```text
这里必须是数据
```

用户输入永远不会被解释成 SQL 命令。

---

# 两份讲义之间的联系

实际上 SQL Injection 讲义是在具体说明第一份课里的一个核心原则：

### Security by Design

不要事后补漏洞。

而要在设计阶段确保：

```text
Data ≠ Control
```

否则：

```text
Bug
 ↓
Vulnerability
 ↓
SQL Injection
 ↓
Exploitation
```

这正好对应第一份讲义中的：

**Bug → Vulnerability → Exploitation** 安全演化链条。
