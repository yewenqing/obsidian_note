# 课程笔记：安全工程与网络安全（第4周）

**主题**：内部人员与机密性 (Insiders & Confidentiality)

**课程代码**：COMP6441 / COMP6841

**讲师**：Rahat Masood

## 1. 基础概念复习 (Recap)

- **机密性 (Confidentiality)**：确保信息只能被授权的人员访问。这是通过保护敏感数据、防止未授权访问或泄露来维护信任和法律合规性的核心机制。
    
- **实现机密性的两种经典方式**：
    
    - **对称密钥加密 (Symmetric Key Cryptography)**：加密和解密使用相同的密钥。速度快，但密钥分发（Key Distribution）具有挑战性。
        
    - **非对称加密 (Asymmetric Encryption)**：使用一对密钥（公钥和私钥）。
        

### 数据加密标准 (DES) 复习

- **概述**：输入为64位明文，使用56位密钥，共经过16轮费斯妥（Feistel）结构进行变换。每轮涉及扩展、S盒代换、置换和密钥混合。
    
- **核心概念**：
    
    - **混淆 (Confusion)**：隐藏密钥与密文之间的关系（DES中通过**S盒代换**实现）。目标是让密钥到输出的关系难以预测。
        
    - **扩散 (Diffusion)**：将单个明文位的变化效果扩散到多个密文位中（DES中通过**置换和重复轮次**实现）。目标是消除密文中的统计模式。
        
    - **雪崩效应 (Avalanche Effect)**：输入或密钥的微小变化会导致输出（密文）发生巨大的、不可预测的改变。期望中大约有一半的密文位会发生改变。
        
- **DES失效原因**：56位的密钥长度过短，在现代硬件下极易遭受暴力破解（Brute-force attack）。1998年，EFF便利用定制机器在不到3天的时间内破解了DES密钥。
    
- **过渡方案 (3DES)**：作为向AES过渡的临时方案，3DES执行“加密-解密-加密”过程，拥有112位或168位密钥，虽然速度较慢，但比原始DES更安全。在网络线上环境下使用效率较低。
    

## 2. 高级加密标准 (AES)

- **基本性质**：一种对称密钥算法，由Joan Daemen和Vincent Rijmen于1998年提出，并于2001/2002年被NIST确立为DES的替代者。它比DES更安全且速度更快，广泛应用于Wi-Fi、VPN和SSL中。
    
- **三个版本**：AES-128（128位数据，128位密钥）、AES-192以及AES-256。
    
- **工作机制**：基于**代换-置换网络 (Substitution-Permutation Network)**。它不是费斯妥密码，不将块分成两半，而是在每轮中对整个4x4的字节状态矩阵（State）进行迭代操作。
    
- **AES-128的10轮加密步骤**：
    
    1. **初始轮 (Initial round)**：与初始密钥进行异或（Key XOR / AddRoundKey）。
        
    2. **第1到第9轮**：每轮包含四个步骤：
        
        - **SubBytes**：通过静态的8位S盒（Substitution Box）对状态矩阵的每个字节进行独立代换（实现混淆）。通过将字节拆分为两个4位半字节（Nibble）确定S盒的行与列进行转换。
            
        - **ShiftRows**：将状态矩阵的行分别循环向左平移固定偏移量（第0行不移，第1行移1字节，第2行移2字节，第3行移3字节）。
            
        - **MixColumns**：利用固定矩阵在有限域 $GF(2^8)$ 上与状态矩阵的列进行线性混合乘法。
            
        - **AddRoundKey**：将每轮生成的轮密钥与状态矩阵按位异或。
            
    3. **最终轮 (Final round)**：包含SubBytes、ShiftRows和AddRoundKey，**不进行MixColumns操作**。
        
- **考试提示**：考试不会要求直接手动计算或推导AES密文，重点在于理解其网络安全概念与设计原理（如：不引入ShiftRows操作会带来什么安全隐患等开放性思考）。
    

## 3. 非对称加密与 RSA

- **非对称加密核心原理**：
    
    - 使用一对密钥：公钥（Public key）所有人可见，用于加密；私钥（Private key）仅由所有者保管，用于解密。
        
    - 依赖于**单向陷门函数 (Trapdoor One-Way Function)**：正向计算非常容易（下坡），反向推导在计算上是不可行的（上坡），但若知道某个“秘密/陷门”（私钥短路路径），反向解开则变得非常容易。
        
    - **混合加密实践**：在实际系统中，由于非对称加密计算量大，通常仅用于安全地建立或交换会话密钥（Session Key），而实际的大宗块数据随后使用更快的对称算法（如AES）进行bulk加密。
        
- **RSA算法 (1977)**：基于大素数分解的数学困难性。
    
    - **密钥对生成步骤**：
        
        1. 选择两个互异的大素数 $p$ 和 $q$（通过米勒-拉宾等素性检验测试确认）。
            
        2. 计算模数 $n = p \times q$。
            
        3. 计算欧拉函数 $\phi(n) = (p-1) \times (q-1)$。
            
        4. 选择一个公开指数 $e$，满足 $1 < e < \phi(n)$ 且 $gcd(e, \phi(n)) = 1$（即 $e$ 与 $\phi(n)$ 互素）。
            
        5. 计算私有指数 $d$，使其满足 $e \times d \equiv 1 \pmod{\phi(n)}$ （即 $d$ 是 $e$ 在模 $\phi(n)$ 下的逆元）。
            
        6. 公钥为 $(e, n)$，私钥为 $(d, n)$。
            
    - **加密**：$c = m^e \bmod n$。
        
    - **解密**：$m = c^d \bmod n$。
        
- **双向机制（认证与数字证书）**：
    
    - **机密性**：发送方用接收方的公钥加密，确保只有拥有对应私钥的接收方能解密。
        
    - **身份认证 (Authentication)**：发送方（如Bob）用自己的私钥加密，接收方用发送方的公钥解密。如果能成功解密，则证明该消息确由该私钥所有者发送。这是数字证书和数字签名的核心基础。
        
- **密码学在实际中的失效原因**：通常**不是因为数学原理被攻破**，而是因为错误的实现或糟糕的密钥管理（例如：使用过短的密钥、弱随机数生成器、缺少填充机制、密钥复用、私钥泄露以及未校验过期的证书）。
    

## 4. 默克尔谜题 (Merkle Puzzles)

- **本质**：最早的公开密钥交换机制之一。它不是一种加密算法，而是一种**在不安全通道上安全分发/共享对称密钥的方法**。
    
- **基于计算不对称性 (Computational Asymmetry)**：对合法用户来说相对容易，但对攻击者而言计算代价极高（大致呈二次方差距 $O(m \times n)$）。
    
- **工作流程**：
    
    1. **谜题生成**：Alice 生成 $m$ 个（例如1024个）加密谜题。每个谜题中包含一个唯一的ID和对应的对称密钥（形式如：$Enc_k(ID_i \parallel Secret\_key_i)$）。Alice 使用**极弱的加密算法**进行加密，使暴力破解对单个谜题是可行的。
        
    2. **谜题解决**：Bob 随机挑选其中一个谜题，通过中等程度的暴力破解（花费 $O(n)$ 计算量）将其解开，获取里面的 $ID$ 和会话密钥。
        
    3. **密钥协商**：Bob 在不安全通道上**以明文形式**将解出来的谜题 $ID$（例如 ID 341）发回给 Alice。
        
    4. Alice 收到 $ID$ 后，在自己的列表中查出对应的密钥，双方成功建立共享密钥。
        
- **为什么Eve（窃听者）难以破解？**：Eve虽然能在不安全通道上听到Bob发回的明文“ID 341”，但Eve并不知道这个ID隐藏在1024个加密信封里的哪一个当中。为了找到这个密钥，Eve不得不暴力破解**所有的谜题信封**，计算代价为 $O(m \times n)$。
    

## 5. 攻防场景与模型

### 中间人攻击 (Man-In-The-Middle, MitM)

- **定义**：攻击者在两个通信方之间秘密拦截并转发通信，对两端伪装成合法的通信对象，而通信双方均毫不知情。
    
- **危害**：攻击者能够篡改消息、记录机密信息、注入恶意命令，甚至在握手初期伪造和替换公钥（例如Eve拦截Alice对Bob公钥的请求，并向Alice发送Eve自己的公钥，从而能够解密Alice发出的所有后续信息）。
    
- **防御手段**：仅仅依靠加密是不够的，必须引入**强认证机制（Authentication）**和**完整性校验**，例如数字证书/公钥基础设施 (PKI)、数字签名以及已认证的密钥交换协议。
    

### 洛卡尔定律 (Locard's Principle) 与数字取证

- **核心核心**：“凡有接触，必留痕迹” (Every contact leaves a trace)。
    
- **在网络安全中的体现**：互联网上的任何数字化操作都会在系统中留下数字化证据、日志或元数据（Metadata）。
    
    - _例如_：用户登录服务器会留下 SSH/认证日志；访问网站会留下 Web 服务器日志（IP、时间戳、User Agent）；恶意软件运行会改变注册表、产生进程日志和文件变更痕迹。
        
- **中间人攻击留下的痕迹**：在现实遭受诸如ARP欺骗导致的中间人攻击时，可通过分析网关的 **ARP 缓存表变化**、DHCP 表、网络延迟/流计时时间戳、以及操作系统日志来追溯攻击痕迹。
    

### 钟摆安全模型：贝尔-拉帕杜拉模型 (Bell-Lapadula Model, BLP)

- **定位**：一种专注于维护系统**机密性**的正式访问控制模型（20世纪70年代为军事系统设计）。访问控制与加密互为补充，通过定义不同的安全分级来防止未授权披露。
    
- **两大核心安全属性（强制访问控制属性）**：
    
    1. **无向上读 (No Read Up / 简单安全性性质)**：低 clearance 的用户不能读取更高级别 classification 的文件（例如：机密级（Confidential）用户无法读取秘密级（Secret）文件）。
        
    2. **无向下写 (No Write Down / $\star$-性质)**：高 clearance 的用户不能将高密级的数据写入到低密级的文件中，防止高密级信息的无意泄露（例如：秘密级（Secret）用户无法将秘密数据复制保存到不安全/非密级（Unclassified）文件中）。
        

## 6. 现代安全演进：零信任架构 (Zero Trust Security)

- **核心宣言**：**“永不信任，始终验证” (Never Trust, Always Verify)**。
    
- **基本假设**：彻底打破传统边界安全防御思维。传统安全默认内部是安全的，而零信任认为**边界已不复存在，攻击者很有可能已经潜伏在网络内部（不论内部人员还是外部连接均不可信）**。
    
- **四大核心原则**：
    
    1. **显式验证 (Verify explicitly)**：在授权访问前，必须严密检查用户的身份、设备状态、所处位置和关联风险。
        
    2. **使用最小特权 (Use least privilege)**：仅授予用户当前任务所需的最小访问权限（可借助BLP等模型和短期临时会话密钥实现，按需知悉、临时提供访问）。
        
    3. **假设已遭入侵 (Assume breach)**：将系统设计成攻击者已然存在的状态，限制攻击横向移动的空间。
        
    4. **持续监控与审计 (Monitor continuously)**：在授予访问权限后，全量记录、分析其操作行为与日志，通过SIEM等系统监测异常指标。
        

## 7. 前沿概念：零知识证明 (Zero-Knowledge Proof, ZKP)

- **定义**：允许证明者（Prover）向验证者（Verifier）证明自己知晓某项秘密/信息的正确性，但**无需向验证者透露该秘密/信息本身的任何实质内容**。
    
- **现实比喻（暗箱烤蛋糕）**：证明者进入一个全黑的黑箱房间里按照秘密配方烤出一个一模一样的蛋糕。如果能连续多次重复这一过程，就能在不向外界展示配方和烘焙细节的前提下，让所有人确信他确实掌握了配方。
    
- **密码学应用示例**：证明你知晓某个密码，但无需在网络上发送该密码或其派生明文数据，从而彻底杜绝身份凭证在传输或存储时泄露的隐患。
    
- **三大核心数学属性**：
    
    1. **完备性 (Completeness)**：如果证明者确实知道该秘密，且诚实遵守协议，验证者必定会接受该证明。
        
    2. **可靠性/正确性 (Soundness)**：如果证明者不知道秘密，他无法通过作弊或欺骗轻易伪造证明来通过验证。
        
    3. **零知识性 (Zero-knowledge)**：在协议交互结束后，验证者除了确信“证明者知道该秘密”这一事实外，无法获取关于该秘密本身的任何额外知识。
