## 1. 操作系统角色与运行模式

- 两大核心功能：
    
    -   ：屏蔽硬件细节，提供标准化高层抽象（内存、文件、I/O 等），提高代码可移植性与安全性。
    - 资源分配器：依据系统策略（公平、隔离、效率）仲裁、分配 CPU、内存、文件等。
    
- 非角色：不是计算机的“特权组件”（它是一种软件）。
- 双模式保护：
    
    - 用户态：限制特权指令（如清除中断）和内存访问权限，隔离进程。
    - 内核态：拥有全量硬件控制权，防范应用规避或控制操作系统。
    

## 2. 系统调用 (Syscall)

- 常规执行流程（以 `uptime` 为例）：
    
    1. 应用调用 C 库函数 $\rightarrow$ C 库按硬件规范设置传参 $\rightarrow$ 触发陷入（MIPS 架构使用 `syscall` 指令）。
    2. CPU 控制权交予内核 $\rightarrow$ 内核保存用户态上下文 $\rightarrow$ 执行安全与合理性检查。
    3. 内核执行请求（如复制开机秒数计数器） $\rightarrow$ 恢复用户态上下文 $\rightarrow$ 返回值压栈/存入寄存器 $\rightarrow$ 返回用户空间。
    4. C 库读取对应栈/寄存器数据，返回给应用。
    
- 内存传参风险（为何比寄存器更需谨慎）：
    
    - 越界风险：应用提供的指针可能是非法或越界的内存区域。
    - 缺页风险：页面已被置换（Page out）到磁盘。
    - 动态篡改（TOCTOU 竞态）：多线程应用中，输入内存可能在内核访问期间被其他线程动态修改。
    

## 3. 进程与线程 (Process & Thread)

- 进程三状态：运行态（Running）、就绪态（Ready）、阻塞态（Blocked）。
- 多任务并发实现：
    
    - 抢占式：时钟中断触发内核，在时间片（Timeslice）到期时强制进行上下文切换。
    - 协作式：靠应用偶尔主动让出（Yield）CPU。
    
- 属性区分：
    
    - 进程独有：地址空间、打开的文件（资源）、PID、进程组、父进程、信号处理程序。
    - 线程独有：调度参数、寄存器、PC、PSW、SP、线程状态。
    
- 就绪队列：存储当前未运行但已具备恢复执行能力的线程。
- 内核/用户级线程 (ULT)：
    
    - ULT 机制：应用内部实现创建、调度，多路复用至单个内核线程。
    - ULT 优点：可定制调度算法、无需陷入内核（速度快）、跨平台、可创建极多线程。
    - ULT 缺点：必须协作式让出 CPU；一人阻塞导致全进程阻塞；无法利用多核 CPU 优势。
    
- 时钟中断与上下文切换步骤：  
    `线程1运行` $\rightarrow$ `时钟中断` $\rightarrow$ `陷入内核` $\rightarrow$ `切到线程1内核栈` $\rightarrow$ `保存线程1用户寄存器` $\rightarrow$ `调度器选出线程2` $\rightarrow$ `切换到线程2内核栈/刷新TLB/更新TCB` $\rightarrow$ `恢复线程2用户寄存器` $\rightarrow$ `切入线程2` $\rightarrow$ `线程2运行`。

## 4. 并发与死锁 (Concurrency & Deadlock)

- 竞态条件与临界区：并发未加协调访问共享资源导致不一致为竞态；访问共享资源的代码段为临界区。
- 临界区方案 4 条件：① 互斥；② 通用性（不假设 CPU 速度/数量）；③ 空闲让进（区外进程不阻塞他人）；④ 有限等待（不无限期等待）。
- 开关中断法：单核简单高效；但多核无效、只能在内核态使用、降低中断响应、易导致整机阻塞。
- Test-and-Set 指令：原子指令。读取并返回锁原值，同时将锁置 1。若原值为 0 抢锁成功，若为 1 抢锁失败。
- 死锁 4 必要条件：① 互斥；② 占有并等待；③ 不可抢占；④ 循环等待。
- 死锁 4 种处理策略： 
    
    - 忽略：鸵鸟策略。适用于发生率极低、其他策略代价高时。
    - 检测与恢复：检测有向环（单实例有效）或使用资源矩阵。恢复靠抢占（夺走资源）、回滚（恢复检查点）或杀死进程。有活锁风险。
    - 避免：动态检查安全状态（Safe State），确保至少存在一条完成路径（如银行家算法）。不实用（需预知最大资源需求）。
    - 预防：破坏 4 条件之一。最实用是破坏循环等待（所有进程严格按相同顺序获取资源）；破坏占有并等待（拿不到全放开）易引发活锁。
    

## 5. 文件系统 (File System)

- 稀疏文件：大部分为空的文件，磁盘仅存元数据记录空块，不写实际空空间，节约空间。
- 大块大小（Block Size）权衡：
    
    - 优势：更快的顺序访问（减少 I/O 次数）；元数据开销少，提高大文件存储经济性。
    - 劣势：增加内部碎片（小文件浪费严重）；随机访问小数据时加载冗余数据，速度变慢。
    
- 分配策略：索引分配（Indexed Allocation）最适合随机访问（常数级访问时间）。
- 位图分配：区域集中、找连续空闲块快；但位图占空间、检索空闲块计算开销大。
- Inode 引用计数：记录指向该 Inode 的目录项数量。多个目录项指向同个 Inode 即为硬链接。
- 缓冲区缓存（Buffer Cache）：
    
    - 缓冲（Buffering）：解决传输单位不一致（如改 1 字节需缓冲整块）。支持异步后台写提升性能（牺牲断电鲁棒性），支持预读（Read Ahead）。
    - 缓存（Caching）：内存中保留用过的数据供后续直接读取。基于局部性原理（空间与时间局部性）。
    

## 6. 内存管理与虚拟内存 (Memory Management)

- 四种传统动态分配算法：
    
    - _首次适应 (First fit)_：从头扫描，用第一个大小合适的块。实际常用（执行快）。
    - _下次适应 (Next fit)_：从上次分配处扫描，用第一个合适的块。实际常用（执行快）。
    - _最佳适应 (Best fit)_：遍历链表，用满足要求的最小块。产生极小无用碎片，慢。
    - _最差适应 (Worst fit)_：遍历链表，用最大块。期望切分后剩下的块足够大，慢。
    
- 分页虚拟内存架构：
    
    - 物理内存拆分为物理页框（Frames）；地址空间拆分为虚拟页（Pages）。
    - 通过页表（Page Table）实现映射；硬件 MMU 负责地址翻译，TLB 充当相联存储器缓存页表项。
    
- 分页系统优势（对比交换机制）：抽象物理结构、支持页面共享、支持部分加载（提高并发度）、无外部碎片、物理上无需连续、上下文切换快、支持超物理内存的虚拟地址空间。
- 工作集（Working Set）：进程在某特定时间窗口内访问过的页面集合，反映局部性。
- 大页面（Page Size）权衡：
    
    - 优势：页表体积小、TLB 覆盖范围大、大块磁盘传输提高吞吐量（降低寻道/旋转延迟影响）。
    - 劣势：增大页面内部碎片、缺页异常时传输单页延迟高。
    
- 页面调入策略：请求调页（按需，常用）与预调页（预测批量，不常用，因预测不准且浪费 I/O）。
- 驻留集调整：监控应用的缺页发生频率（PFF）。高于阈值多分派页框，低于阈值削减回收。
- 四种页面置换算法：
    
    1. _最佳算法 (Optimal)_：淘汰未来最久不用的页。无法实现，仅作理论基准。
    2. _最近最少使用 (LRU)_：淘汰过去最久未用的页。开销大，访存需更新时间戳，难高效实现。
    3. _时钟算法 (Clock)_：访问时置引用位为 1。指针扫描遇到 1 清 0 并前进，遇到 0 则淘汰。LRU 的高效工程近似，最常用。
    4. _先进先出 (FIFO)_：淘汰驻留最久的页。无视访问频率，易淘汰高频热页。
    

## 7. 多处理器系统 (Multiprocessor Systems)

- 自旋锁（Spinlock） vs 阻塞锁（Blocking Lock）：
    
    - 单核：自旋锁不适用。自旋占满 CPU 导致持锁者无法运行和释放锁，必须使用阻塞锁。
    - 多核：若持锁线程在另一核活跃运行，且平均自旋等待时间 < 上下文切换开销，则自旋锁更合适。
    
- 单就绪队列多核弊端：
    
    - 锁竞争瓶颈：多个处理器同时访问会引入严重锁竞争。
    - 缓存命中率低：无法保证进程在同一 CPU 上连续运行（亲和性差），导致大量 Cache Miss。
    - _注：若 CPU 核心极少，因其实现简单且自带负载均衡，单队列亦可接受。_
