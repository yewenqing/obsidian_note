**描述外部碎片与内部碎片之间的区别。指出在以下两种机器中哪一种最可能成为问题：a) 使用基址-界限寄存器和静态分区的简单内存管理机器，b) 使用动态分区的类似机器。**

  

  

- **内部碎片**：已分配内存区域内部未被使用的浪费空间。分配给进程的内存可能大于其实际请求的内存。
    
      
    
- **外部碎片**：已分配内存区域外部的浪费空间。虽然系统总空闲内存足以满足分配请求，但由于这些空间并不连续而无法使用。
    
      
    
- **静态分区**更容易受到**内部碎片**的影响，因为分配给每个进程的内存大于其实际所需，且所需的分区大小可能无法被最小分配单元整除。
    
      
    
- **动态分区**更容易受到**外部碎片**的影响，因为动态分区从较大的空闲内存块中恰好切出进程所需大小的内存，留下的内存碎片往往太小而无法利用。采用动态分区的机器可以使用内存紧缩（Compaction）来减少外部碎片。
    
      
    

==**列出并描述课程中讲解的四种内存分配算法。这四种算法中哪两种在实际应用中更常用？**==

  

  

- ==**首次适应（First fit）**：从内存起始位置开始扫描，分配到找到的第一个大小合适的空闲块中。==
    
      
    
- ==**下次适应（Next fit）**：从上一次分配的位置继续往下扫描，分配到找到的第一个可用空闲块中。==
    
      
    
- ==**最佳适应（Best fit）**：遍历整个内存链表，寻找满足要求的最小空闲块并放入其中，理由是这样留下的无用碎片最小。==
    
      
    
- ==**最差适应（Worst fit）**：遍历整条链表并放入最大的空闲区域，理由是切分后剩下的空闲块很可能足够大，能供其他进程使用。==
    
      
    
- ==**首次适应和下次适应**在实际中更为常用，因为它们不需要遍历整条链表，执行速度比最佳适应和最差适应更快。==
    
      
    

**基于基址-界限寄存器的 MMU 可以支持交换。什么是交换？交换能否允许一个需要 16M 内存的应用程序在只有 8M RAM 的机器上运行？**

  

  

- 交换（Swapping）是指将一个完整的进程调入主存运行一段时间，随后再将其完整放回磁盘，反之亦然。它用于系统物理主存不足以同时容纳所有当前处于活动状态的进程的场景。
    
      
    
- 假设该应用程序由一个程序构成（即单一进程），交换**无法**允许一个需要 16M 内存的应用程序（进程）在拥有 8M RAM（主存）的机器上运行，因为整个进程的体积过大，无法完整装入主存中。
    
      
    

==**描述基于分页的虚拟内存。在你的回答中应涵盖页、页框、页表和内存管理单元。**==

  

  

- ==物理内存被划分为大小相等的**物理页框（Frames）**。==
    
      
    
- ==进程的地址空间被划分为大小相等的**虚拟页（Pages）**。每个进程都获得了一种在其专属地址空间中运行的假象。==
    
      
    
- ==页与页框的大小相同。通过页表（Page Table）将虚拟页映射到物理页框。==
    
      
    
- ==内存管理单元（MMU）是一套硬件机制，它利用页表将虚拟地址转换为物理地址。转换检测缓冲区（TLB）是 MMU 的一种常见实现形式，它利用相联存储器（Associative Memory）缓存最近使用过的页表项。==
    
      
    
- ==当物理内存满时，近期未被使用的页面可以被写出到磁盘上。它们此前占用的页框可以分配给新页面使用。磁盘上的页面可以根据需要重新加载回主存。==
    
      
    

==**相比于实现了交换机制的简单基址-界限寄存器系统，列举基于分页的虚拟内存系统的一些优势。**==

  

  

- ==抽象了物理内存的组织结构。==
    
      
    
- ==支持进程间共享页面。==
    
      
    
- ==支持将进程部分加载到内存中，通过允许更多进程处于活跃状态来提升系统性能。==
    
      
    
- ==无外部碎片。==
    
      
    
- ==在分页机制下，进程在物理内存中不需要保持连续。==
    
      
    
- ==避免了在交换时从磁盘全量加载整个进程的昂贵开销，使上下文切换速度更快。==
    
      
    
- ==支持大于物理内存容量的虚拟地址空间。==
    
      
    

**什么是转换检测缓冲区？它包含的每个表项中存储了什么内容？**

  

  

- 转换检测缓冲区（TLB）是用于缓存最近使用的页表项的高速相联硬件缓存。它是内存管理单元（MMU）的一种常用实现。
    
      
    
- 最基础的 TLB 将虚拟页号（VPN）映射到物理页框号（PFN）。
    
      
    
- TLB 表项还可能包含地址空间标识符（ASID），以及指示该表项是否有效（Valid）、已缓存（Cached）、已引用（Referenced）或全局有效（Global）的标志位。
    
      
    

**某些 TLB 支持地址空间标识符（ASID）。为什么？**

  

  

- 支持 ASID 的 TLB 被称为**带标签的 TLB（Tagged TLB）**。
    
      
    
- 在不支持 ASID 的 TLB 中，切换到另一个地址空间时必须**刷新（Flush）TLB**（使所有表项失效），因为无法判断某个 TLB 表项是否属于当前地址空间 —— TLB 在所有进程间共享，但每个页表项仅对单一进程有效。这一清空过程耗时较长。
    
      
    
- 在 Tagged TLB 中，只需切换当前的 ASID，并在每次页面引用时比对 TLB 表项的 ASID 与当前 ASID 是否匹配即可。这减少了上下文切换所需的时间，并允许多个进程同时在 TLB 中保留“热”表项，避免了上下文切换后高昂的 TLB 未命中开销。
    
      
    

==**描述二级页表。它与简单的单层页表数组相比有何异同？**==

  

  

- ==二级页表负责将虚拟页号映射为物理页框号。==
    
      
    
- ==它与单层平铺页表数组的不同之处在于：二级页表并非为每一个表项都预先分配内存。二级页表仅在其包含常驻/已映射的虚拟页时，才会为对应的二级表分配内存空间。==
    
      
    
- ==因此，二级页表平均占用的内存远少于简单的单层页表。但二级页表查找映射关系需要进行 2 次内存访问而非 1 次，属于以轻微的性能代价换取内存空间的节省。==
    
      
    
- ==以拥有 4KB 页面/页框的 32 位（4GB）虚拟地址空间为例：顶级页表（包含 1024 个指向二级数组指针的数组）通过虚拟地址的高位（`VADDR[31:22]`）进行索引，以查找二级数组（包含页框号和权限的页表项），再使用部分低位（`VADDR[21:12]`）对该二级表进行索引。==
    
      
    
- ==单层平铺页表数组所需内存：==
    
      
    
    $$\begin{aligned} \text{页表大小} &= 2^{20} \text{ 个 PTE} \times 4 \text{ 字节} \\ &= 2^{22} \text{ 字节} = 4\text{ MB} \end{aligned}$$
    

**什么是倒排页表？它与二级页表相比有何异同？**

  

  

- 倒排页表（Inverted Page Table, IPT）是按物理页框号排序索引的页面列表。倒排页表通过对虚拟地址的页号进行哈希计算来查询页表，进而匹配页号（或通过链表结构寻找对应页面），其索引即为物理页框号。
    
      
    
- 传统页表的大小与**虚拟地址空间大小**成正比。这在 64 位机器上尤为致命（如果虚拟地址空间为 $2^{64}$ 字节即 16 Exabytes，维护多级页表需要过多的间接层级，既缓慢又消耗海量存储空间）。
    
      
    
- 倒排页表是以物理页框号为索引的页号数组，通过哈希虚拟地址来定位页框表项。其最重要的优势在于：**页表大小仅与物理内存（RAM）大小相关，而与虚拟内存大小无关**。倒排页表非常适合寻址空间极大但物理内存相对较小的系统（例如 64 位寻址但只有 2GB RAM 的机器）。
    
      
    

**什么是时间局部性和空间局部性？**

  

  

- **时间局部性（Temporal locality）**：最近被访问过的内存项在不久的将来很可能会被再次访问。
    
      
    
- **空间局部性（Spatial locality）**：在空间地址上彼此相邻的内存项，很倾向于在相近的时间段内被连续访问。
    
      
    

**什么是进程的工作集？**

  

  

- ==进程的工作集（Working Set）是指该进程在某段特定时间窗口内所访问过的所有页面的集合，它近似反映了进程的局部性特征。==
    
      
    

**特定体系结构的页面大小如何影响工作集的大小？**

  

  

- 若页面尺寸较小，工作集的大小也更小（从实际占用的内存容量而言，而非绝对页面数量），因为较小的页面能更精准地反映当前的内存使用情况（即页面内部包含的无关数据较少）。
    
      
    
- 若页面尺寸较大，工作集也会随之增大，因为较大页面中包含的更多无关数据也被一并计入了当前工作集中。
    
      
    

**什么是系统抖动？如何检测系统抖动？一旦检测到，应如何从中恢复？**

  

  

- 当所有进程的工作集大小之和超过了物理内存的总容量时，就会发生**系统抖动（Thrashing）**。
    
      
    
- 发生抖动时，某个进程发生缺页，置换出页面并阻塞等待 I/O；紧接着下一个进程也发生缺页、置换页面并阻塞等待磁盘调入页面。这种情况在其他进程间连锁循环，导致**缺页率急剧上升而 CPU 利用率骤降**，系统可通过监控这一特征来检测抖动。
    
      
    
- 恢复抖动的方法是**挂起（Suspend）若干进程**，将其驻留集换出到后备存储区（磁盘）。这为剩余进程腾出了物理内存空间，使其能够将工作集缺失的页面调入内存。此外，扩充物理 RAM 也可以避免抖动。
    
      
    

==**列举增大页面大小的一些优缺点。**==

  

  

- ==**优点：**==
    
      
    - ==缩减页表本身的体积。==
        
          
        
    - ==扩大 TLB 的内存覆盖范围。==
        
          
        
    - ==提高交换/换页的 I/O 吞吐量，因为小规模磁盘传输的耗时主要被寻道时间和旋转延迟所主导。==
        
          
        
- ==**缺点：**==
    
      
    - ==增加了缺页异常的延迟，因为单页数据量更大导致换页传输响应更慢。==
        
          
        
    - ==增大了页面的**内部碎片** —— 针对较小的数据片段，页面内潜在被浪费的空间更多。==
        
          
        

==**描述两种虚拟内存页面调入策略。哪一种在实际中不太常用？为什么？**==

  

  

- ==**请求调页（Demand paging）**：仅在发生缺页异常时才按需调入对应页面。==
    
      
    
- ==**预调页（Prepaging）**：尝试在进程访问页面之前提前预测并批量调入。==
    
      
    
- ==**预调页在实际中不太常用**，原因包括：==
    
      
    - 若调入了非必需的页面，会白白浪费 I/O 带宽。
        
          
        
    - 预测算法实现困难。
        
          
        
    - 可能会将当前工作集中的有效页面误置换出内存，替换成并未使用的页面。
        
          
        

==**我们可以观察哪种操作系统事件，并将其作为决定应用程序分配多少页框（即决定应用程序驻留集大小）的算法输入？**==

  

  

- ==可以监控应用程序的**缺页发生频率（Page Fault Frequency, PFF）**，并将其与理想的缺页频率阈值进行比对。如果某个应用程序的缺页频率过高，则为其多分派一个物理页框；反之若过低，则削减回收其页框。==
    
      
    

==**列出并描述四种页面置换算法。对它们进行批判性对比。**==

  

  

==_按讲义中性能从优到劣排列：_==

  

  

1. ==**最佳置换算法（Optimal）**：利用“时光穿越”找出未来最长时间内不会被访问的页面并将其淘汰。该算法在实际中无法实现（需要预知未来），仅作为评估其他算法优劣的理论基准线。==
    
      
    
2. ==**最近最少使用算法（LRU）**：计算并淘汰过去最长时间未被访问的页面。在实际中很难高效实现，因为需要在每次访存时都记录或更新时间戳。==
    
      
    
3. ==**时钟页面置换算法（Clock）**：页面被访问时将其“引用位（Referenced bit）”置为 1。寻找淘汰目标时，若遇到 1 则清零，并直接淘汰遇到的第一个引用位为 0 的候选页，下一次查找从上次淘汰位置继续。它是 LRU 的一种高效、可落地的工程近似实现，广泛应用于实际操作系统中。==
    
      
    
4. ==**先进先出算法（FIFO）**：淘汰驻留时间最长的页面。该算法在置换决策中完全不考虑实际内存访问频率，可能会将系统中被最频繁访问的高频热页淘汰出局。==
