==**什么是竞态条件？请举例说明。**==

==当多个进程/线程未加协调地并发访问共享资源（例如内存或设备寄存器）时，就会发生竞态条件，这会导致死锁、数据丢失或产生不正确、不一致的程序行为。==

  

例如两个进程同时更新一个计数器。假设计数器的初始值为 1。

在理想情况下会发生：

  

- 进程 A 读取计数器为 1。
    
      
    
- 进程 A 将计数器从 1 递增到 2。
    
      
    
- 进程 B 读取计数器为 2。
    
      
    
- 进程 B 将计数器从 2 递增到 3。
    
      
    

然而，实际中也可能发生以下交错情况：

  

- 进程 A 读取计数器为 1。
    
      
    
- 进程 B 读取计数器为 1。
    
      
    
- 进程 A 将计数器从 1 递增到 2。
    
      
    
- 进程 B 将计数器从 1 递增到 2，覆盖了进程 A 写入的计数值（最终结果仍为 2）。
    
      
    

==**什么是临界区？临界区与控制共享资源的访问有何关系？**==

==临界区是指访问共享资源的代码区域==。因此，我们需要协调对临界区的访问，以确保代码执行结果的确定性。这通常意味着确保当一个线程正在临界区内执行时，其他线程不能修改或查看这些共享资源。

  

==**解决临界区问题的任意方案必须满足哪四个必要条件？为什么需要这些条件？**==

  

- ==**互斥（Mutual Exclusion）**：不能有两个进程同时处于临界区内。==
    
      
    
- ==**通用性 / 无假设（No assumptions）**：不对 CPU 的运行速度或数量做任何假设。==
    
      
    
- ==**空闲让进 / 前进性（Progress）**：在临界区外运行的进程不得阻塞其他试图进入临界区的进程。==
    
      
    
- ==**有限等待（Bounded Waiting）**：任何进程都不能无限期等待进入其临界区。==
    
      
    

**为什么轮流机制是解决临界区问题的一个糟糕方案？**

  

- 即使另一个线程正在处理不相关的事务，当前线程也必须被动等待轮到自己。
    
      
    
- 如果不同线程使用临界区的频率不同，整体性能会受限于使用频率最低的那个线程，即系统只能以最慢线程的速率向前推进。
    
      
    
- 如果某个线程不再需要轮到自己（退出或不再使用），另一个线程可能会彻底无法继续运行。
    
      
    

==**禁用和启用中断是实现互斥的常用方法。它有什么优点和缺点？**==

  

- ==**优点**：==
    
      
    - ==在单处理器（单核）系统上简单且高效。==
        
          
        
- ==**缺点**：==
    
      
    - ==在多处理器系统上无效，因为其他处理器依然可以并行访问共享资源。==
        
          
        
    - ==只能在内核态中使用。==
        
          
        
    - ==会降低中断响应速度；即使其他进程不使用受保护的共享内存，也会一并被阻塞。==
        
          
        

==**什么是测试并设置（Test-and-Set）指令？如何用它来实现互斥？可以结合一段伪汇编代码来辅助说明。**==

==测试并设置（Test-and-Set）是一条原子指令（即不可被中断的操作），它会读取锁的当前值并复制返回其原始值，同时将锁置为 1（锁定状态）。如果读出的锁原值为 0，说明此前未上锁，当前线程成功获得锁；若原值为 1，说明其他线程正持有该锁。==

  

用于 `lock_acquire`（获取锁）和 `lock_release`（释放锁）的伪汇编代码：

  

代码段

```
lock_acquire:
    tsl register, lock          // 尝试设置锁，并将锁的原值复制到 'register'
    cmp register, 0             // 检查锁的原值是否为 0？
    jne lock_acquire            // 若非 0，说明未获取到锁，循环自旋重试
    ret                         // 返回调用者，成功进入临界区

lock_release:
    move lock, 0                // 将锁置为 0 以释放锁
    ret
```

因此，测试并设置指令可以用来实现锁变量，进而用于实现互斥。

  

**什么是生产者-消费者问题？请给出其在操作系统中出现的一个实例。**

生产者-消费者问题涉及对一个有界缓冲区（Bounded Buffer）的填充与消耗。只要缓冲区未满，生产者就可以向其中插入数据条目；只要缓冲区非空，消费者就可以从中读取数据。对缓冲区本身的数据操作通常需要互斥保护。

  

**示例：I/O 缓冲（IO buffering）**

  

- 缓冲区大小是有界的。
    
      
    
- 当用户进程执行读取操作时，I/O 设备是生产者，用户进程是消费者。类似地，当用户进程执行写入操作时，I/O 设备是消费者，用户进程是生产者。
    
      
    

**信号量是一种阻塞式的同步原语。请借助伪代码描述它们的工作原理。你可以假设存在 `thread_block()` 和 `thread_wakeup()` 函数。**

信号量包含两个基本操作：

  

- **P（proberen / 递减 / wait）**：原子地将计数器减 1。如果计数器减后变为负数，当前线程将被阻塞休眠，直到计数器回升至至少为 0。
    
      
    
- **V（verhogen / 递增 / signal）**：原子地将计数器加 1。如果有线程在此信号量上阻塞休眠，则唤醒其中一个线程。
    
      
    

**伪代码：**

  

C

```
P (semaphore sem) {
    sem.count--;
    if (sem.count < 0) {                // 若计数值变为负数，阻塞当前线程
        enqueue(curthread, sem.queue);  // 将当前线程加入信号量等待队列
        thread_sleep(curthread);
    }
}

V (semaphore sem) {
    sem.count++;
    if (sem.count <= 0) {               // 若队列中有被阻塞的进程，唤醒一个
        thread = dequeue(sem.queue);    // 唤醒队首的进程
        thread_wakeup(thread);
    }
}
```

**描述如何使用信号量实现锁。**

可以通过将信号量的初始值设为 1 来实现互斥锁。信号量的计数值本质上是允许进入临界区的实体数量上限，因此当初始值为 1 时，它就起到了锁的作用。示例如下：

  

C

```
semaphore sem = sem_create("sem", 1);   // 初始化信号量为 1
P(sem);                                 // 信号量减 1，获取锁
critical_region();                      // 临界区操作
V(sem);                                 // 信号量加 1，释放锁
```

**什么是管程和条件变量？**

  

- **管程（Monitors）**：是一种旨在简化并发访问控制的编程语言结构。与共享资源相关的代码（以及共享资源本身）被封装在管程内部，编译器会确保同一时刻管程内部最多只有一个线程在执行。当一个线程调用管程方法而管程正在处理另一个线程时，该线程会排队休眠，直到另一个线程退出管程。
    
      
    
- **条件变量（Condition Variables）**：是管程内部用于阻塞和等待特定事件发生的实体。`wait` 操作用于等待事件发生，`signal` 操作用于触发该事件。调用 `wait` 的线程会休眠，直到另一个线程通过 `signal` 将其唤醒。此外，线程还可以调用 `broadcast` 来唤醒所有在该条件变量上阻塞的线程。
