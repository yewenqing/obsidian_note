**1. 什么是分支延迟槽（Branch Delay）？**

  

  

- **解答**：MIPS CPU 的流水线结构决定了当一条跳转指令到达“执行”（execute）阶段并生成新的程序计数器（PC）时，紧随其后的下一条指令其实已经被译码完毕。与其丢弃这部分可能有效的工作，体系结构规范规定：**分支跳转指令紧随其后的那条指令，总是在跳转到目标地址之前被执行**。

- **c. `jr ra` 的作用是什么？**

- **f. 为什么 `arg5` 和 `arg6` 会引用栈？**

**3. C 语言编译器栈管理示例**

  

  

C

```
#include <stdio.h>
#include <unistd.h>

char teststr[] = "\nThe quick brown fox jumps of the lazy dog.\n";

void reverse_print(char *s)
{
  if (*s != '\0') {
    reverse_print(s+1);
    write(STDOUT_FILENO,s,1);
  }
}

int main()
{
  reverse_print(teststr);
}
```

- **a. 逐行解释代码的作用**：
    
      
    - `addiu sp,sp,-24`：在栈上分配 24 字节空间（16 字节为调用子函数预留给 `a0-a3` 的参数槽，8 字节保存 `ra` 和 `s0`）。
        
          
        
    - `sw ra,20(sp)`：将返回地址保存在栈上（因为本函数内部还要调用其他函数，`ra` 会被覆盖）。
        
          
        
    - `sw s0,16(sp)`：`s` 系列寄存器属于被调用者保存（Callee-saved）寄存器，退出前必须恢复原值；此处将其压栈以便在函数内部使用 `s0`。
        
          
        
    - `lb v0,0(a0)`：从第一个参数指向的地址加载一个字符。
        
          
        
    - `nop`：空操作（Load 延迟槽）。
        
          
        
    - `beqz v0,400124`：判断字符是否为 `\0`（0），若是则向前跳转到 `400124` 准备退出。
        
          
        
    - `move s0,a0`：（分支延迟槽）将当前字符串指针保存在 `s0` 中。
        
          
        
    - `jal 4000f0`：递归调用 `reverse_print`。
        
          
        
    - `addiu a0,a0,1`：（分支延迟槽）将指针加 1 作为参数传入，使下一层递归从下一个字符开始。
        
          
        
    - `li a0,1`：将 `write` 的文件描述符参数设为 1（标准输出 `STDOUT_FILENO`）。
        
          
        
    - `move a1,s0`：将保存的字符指针传入 `write` 的第二个参数（由于 `s0` 跨函数调用保持不变，它依然指向当前字符）。
        
          
        
    - `jal 4002bc <write>`：调用 `write` 函数。
        
          
        
    - `li a2,1`：（分支延迟槽）设置 `write` 输出的字节数为 1。
        
          
        
    - `lw ra,20(sp)`：从栈中恢复本函数的返回地址。
        
          
        
    - `lw s0,16(sp)`：恢复 `s0` 的原始值。
        
          
        
    - `jr ra`：返回给调用者。
        
          
        
    - `addiu sp,sp,24`：（分支延迟槽）释放 24 字节栈空间。
        
          
        
- **b. 调用此函数时，栈能增长到的最大深度是多少？**
    
      
    
      
    - **解答**：每次调用 `reverse_print` 都会分配 24 字节的栈帧。由于该函数是递归调用的，栈总分配量为 **24 字节 × 字符串长度**。若字符串无边界限制，递归深度不受限，栈的增长也将不受限制。
        
          
        

**4. 为什么内核程序员要避免使用递归或大型局部变量数组？**

  

  

- **解答**：内核栈（Kernel Stack）通常是大小非常有限的资源。栈溢出会直接导致整台机器崩溃（Panic/Crash）。
    
      
    

**线程（Threads）**

  

  

**5. 比较协作式多线程（Cooperative）与抢占式多线程（Preemptive）**

  

  

- **解答**：
    
      
    - **协作式多线程**：运行中的线程必须显式调用 `yield()` 主动让出 CPU，分派器（Dispatcher）才能选择下一个就绪线程运行。它依赖所有线程的自觉配合来保证各线程均摊 CPU 时间。
        
          
        
    - **抢占式多线程**：由外部事件（例如周期性时钟中断）触发调度分派器，强制**抢占**正在运行的线程并切换至下一个就绪线程。即使存在恶意或不配合的线程，也能强制保证 CPU 时间的规律与公平分配。
        
          
        

**6. 描述用户级线程（User-Level Threads）与内核级线程（Kernel-Level Threads）的优缺点**

  

  

- **解答**：
    
      
    - **用户级线程**在应用程序内实现（通常由线程库管理），线程控制块（TCB）和调度器都在应用程序内部，内核对其完全不知情。
        
          
        
    - **内核级线程**在内核中实现，TCB 由内核维护，并由内核调度器统一调度。
        
          
        
    - **优缺点对比**：
        
          
        - 用户线程的创建、销毁、管理、阻塞和唤醒速度通常更快（无需进出内核模式）。
            
              
            
        - 若单个用户级线程在内核中阻塞，整个进程都会被阻塞（不过部分库会利用非阻塞系统调用来模拟阻塞调用，避免整进程挂起）。
            
              
            
        - 用户线程无法利用多 CPU/多核系统的物理并行能力。
            
              
            
        - 内核线程通常是抢占式的，而用户线程通常是协作式的（部分用户线程库会利用警报或定时器提供时钟滴答以支持抢占）。
            
              
            
        - 用户级线程可以在不支持内核线程的操作系统上实现。
            
              
            

**7. 某 Web 服务器采用多线程架构，若读取文件的唯一途径是常规阻塞式 `read` 系统调用，该服务器使用的是用户级线程还是内核级线程？为什么？**

  

  

- **解答**：必须使用**内核级线程**。当 Web 服务器中的某个工作线程需要从磁盘读取网页时会发生阻塞。若采用用户级线程，该阻塞操作将导致整个进程被挂起，彻底丧失多线程并发的意义。只有使用内核线程，才能在某些线程阻塞时允许其他线程继续执行。
    
      
    

**8. 假设在一个单线程多进程的操作系统中，内核为每个进程维护一个内核控制线程和专属的内核栈。进程切换由函数 `switch_thread(cur_tcb, dst_tcb)` 执行，该函数具体做了什么？**

  

  

- **解答**：
    
      
    - 将满足编译器调用规约所需的寄存器（以及用于返回调用者的寄存器）保存到当前内核栈上。
        
          
        
    - 将当前的栈指针（SP）保存到 `cur_tcb` 对应的控制块中，并将 SP 更新为 `dst_tcb` 中保存的目标栈指针。
        
          
        
    - 从目标（现已成为当前）栈中恢复之前保存的寄存器，然后返回到目标线程上次中断的位置继续执行。
        
          
        

**内核进入与退出（Kernel Entry and Exit）**

  

  

**9. 什么是 `EPC` 寄存器？它有什么作用？**

  

  

- **解答**：这是一个 32 位的异常程序计数器（Exception Program Counter），保存发生上一次异常时的指令返回地址。触发异常的指令地址即为 `EPC` 中的值（若 `Cause` 寄存器设置了 `BD` 分支延迟位，则 `EPC` 指向其前一条分支跳转指令）。异常处理程序利用它在中断处理结束后恢复执行。
    
      
    

**10. 发生异常时，`STATUS` 寄存器中的 `KUc` 和 `IEc` 位会发生什么变化？为什么？如何恢复？**

  

  

- **解答**：
    
      
    - 当前位（`c` 表示 current）被左移推入对应的先前位（`p` 表示 previous）中，随后当前位被置为 `KUc = 0` 且 `IEc = 0`（进入**内核态且禁用中断**）。
        
          
        
    - 这样设计是为了完整保存异常发生时的 CPU 运行状态与中断开关状态，以便在从异常返回时精确恢复。
        
          
        
    - 通过执行 `rfe`（Restore From Exception）指令将其恢复（将 `p` 位弹回 `c` 位）。
        
          
        

**11. 系统调用异常发生后，`Cause` 寄存器中的 `ExcCode` 值是多少？**

  

  

- **解答**：值为 **8**（表示系统调用 Syscall 异常）。
    
      
    

**12. 为什么内核程序员在实现系统调用时必须格外小心？**

  

  

- **解答**：如果系统调用的参数校验不充分或实现存在缺陷，恶意程序或含 Bug 的用户程序可能会导致整个操作系统崩溃或被完全攻破提权。
    
      
    

**13. 关于 MIPS R3000 上 OS/161 系统调用规约的案例分析**

  

  

- **a. C 语言函数调用规约与用户程序和内核之间的系统调用接口有何关联？**
    
      
    
      
    - **解答**：任何系统调用包装函数执行完毕后，外部表现必须严格符合 C 函数调用规约（包括保存和恢复 Callee-saved 寄存器，如 `s0-s8`, `ra`）。此外，系统调用约定直接沿用了 C 编译器的传参寄存器规则，包装函数无需挪动参数位置，编译器已经把参数放到了操作系统期望的位置。
        
          
        
- **b. 保持编译器调用规约的主要工作是由系统调用包装函数完成，还是由 OS/161 内核完成？**
    
      
    
      
    - **解答**：主要由 **OS/161 内核代码**完成（内核负责保存和恢复用户态寄存器），系统调用包装函数本身只做极少的工作。
        
          
        
- **c. 相比于传递给包装函数的参数，跨越内核边界时最少还需要额外提供什么信息？**
    
      
    
      
    - **解答**：至少需要额外提供**系统调用号（System Call Number）**。通常由包装函数将约定的寄存器（如 `v0`）设置为对应的系统调用号。
        
          
        

**14. 在讲义案例中，库函数 `read` 触发了同名的 `read` 系统调用。两者名称必须相同吗？如果不是，哪个名字更重要？**

  

  

- **解答**：除了文档语义外，系统调用本质上并没有名字。当库函数 `read()` 陷入内核时，它只是将系统调用编号存入寄存器或栈中，内核以此编号作为跳转表（如 `switch` 语句）的索引，底层并不存在具体的名字匹配。相反，**库函数的名称非常重要**，因为它是提供给程序员在代码中直接调用的 API 符号。（内核中实现 `read` 的函数命名为 `sys_read` 纯粹是为了代码清晰的工程约定）。
    
      
    

**15. 对程序员而言，系统调用看起来与普通库函数调用无异。程序员是否有必要知道哪些库函数会引发系统调用？在什么情况下需要，为什么？**

  

  

- **解答**：从程序逻辑正确性来看无需区分；但在**关注性能**的场景下至关重要。每次系统调用都会产生用户态到内核态切换的上下文开销。此外，在多用户/多任务系统中，系统调用返回时可能会触发调度器调度其他进程，从而进一步拖慢当前调用进程的实时执行进度。如果某项任务能在用户态完成而无需发起系统调用，程序运行速度会显著提升。
