
### 第 2 周辅导课：问题与解答

#### 一、操作系统导论 (Operating Systems Intro)

**1. 处理器运行在特权模式（Privileged Mode，也称内核模式 Kernel Mode）与用户模式（User Mode）之间有哪些区别？为什么需要这两种模式？**

  

  

> **解答**： 在用户模式下：
> 
>   
> 
> - 无法访问 CPU 控制寄存器。
>     
>       
>     
> - 无法执行 CPU 管理类特权指令。
>     
>       
>     
> - 无法访问部分地址空间（即存放内核代码和数据的区域）。
>     
>       
>     
> - 无法访问某些设备内存和寄存器（或 I/O 端口）。
>     
>       
>     
> 
> 之所以需要这两种运行模式，是为了确保运行在用户模式下的应用程序无法绕过、破坏或夺取操作系统的控制权。
> 
>   

**2. 操作系统的两个主要角色是什么？**

  

  

> **解答**：
> 
>   
> 
> 1. 为程序员提供高层次的抽象机器（隐藏底层硬件的复杂细节）；
>     
>       
>     
> 2. 充当资源管理器，根据既定的系统策略在相互竞争的程序或用户之间分配资源。
>     
>       
>     

**3. 基于对文件系统的高层次理解，解释文件系统是如何实现操作系统的这两个角色的？**

  

  

> **解答**：
> 
>   
> 
> - **抽象机器角色**：在硬件层面上，存储涉及底层的硬件控制器，以及将数据块分散存放在多个位置的物理存储设备。操作系统的文件系统抽象了所有这些底层细节，提供了存储、命名和组织任意非结构化数据的统一接口。
>     
>       
>     
> - **资源管理角色**：文件系统通过管理存储设备上的已分配空间和空闲空间来协调竞争的进程，同时负责执行存储配额与限制（如 Quota 配额机制）。
>     
>       
>     

**4. 下列哪些指令（或指令序列）应当仅允许在内核模式下执行？**

  

  

1. 禁用所有中断。
    
      
    
2. 读取当前时间时钟。
    
      
    
3. 设置当前时间时钟。

>

#### 二、操作系统系统调用接口 (OS system call interface)

**5. 下面的代码使用了典型的 UNIX 进程管理系统调用：`fork()`, `execl()`, `exit()` 和 `getpid()`。请回答下列问题：**

  

  

- a. 在 `fork` 之后，父进程和子进程中的 `i` 的值是多少？
    
      
    
- b. 当子进程更新了 `my_pid` 之后，父进程中的 `my_pid` 值会是多少？
    
      
    
- c. `/bin/echo` 的进程 ID（PID）是多少？
    
      
    
- d. 为什么在正常情况下，`execl` 后面的代码预计永远不会被执行到？
    
      
    
- e. 当 `FORK_DEPTH` 为 3 时，_Hello World_ 会被打印多少次？
    
      
    
- f. 运行该程序共创建/涉及了多少个进程（包括初始的第一个进程）？
    
      
    

C

```
#include <sys/types.h>
#include <unistd.h>
#include <stdlib.h>
#include <stdio.h>

#define FORK_DEPTH 3

main()
{
  int i, r;
  pid_t my_pid;

  my_pid = getpid();
  
  for (i = 1; i <= FORK_DEPTH; i++) {
    r = fork();
    if (r > 0) {
      /* 成功 fork 出子进程后，当前处于父进程中 */
      printf("Parent process %d forked child process %d\n", my_pid, r);  
    } else if (r == 0) {
      /* 当前处于子进程中，因此更新 my_pid */
      my_pid = getpid();
      
      /* 如果达到最大深度则运行 /bin/echo，否则继续循环 */
      if (i == FORK_DEPTH) { 
        r = execl("/bin/echo", "/bin/echo", "Hello World", NULL);
        /* 正常情况下绝不会执行到这里，若执行到此则直接退出 */
        exit(1);
      }
    } else { /* r < 0 */
      /* fork 失败，异常退出 */
      exit(1);
    }
  }
}
```

> **解答**：
> 
>   
> 
> - a. 子进程是一个复制自父进程的全新独立进程。子进程中的 `i` 保留了在调用 `fork` 瞬间父进程中对应的值。
>     
>       
>     
> - b. 父进程中的 `my_pid` 不会受到子进程任何操作的影响；`fork` 之后父子进程是完全相互独立的。
>     
>       
>     
> - c. `execl` 会用指定的可执行文件替换当前运行进程的**内容**，其进程 ID（PID）保持不变。
>     
>       
>     
> - d. 成功的 `execl` 会导致当前代码空间被彻底替换。如果调用成功，它不会返回，因为已经没有原先的代码可供返回执行。
>     
>       
>     
> - e. 当 `FORK_DEPTH` 为 3 时，_Hello World_ 会被打印 **4 次**。
>     
>       
>     
> - f. 执行该代码总共涉及 **8 个进程**。
>     
>       
>     

**6. 关于文件 I/O 代码的问题：**

  

  

- a. 这段代码的作用是什么？
    
      
    
- b. 除了 `O_WRONLY`（只写），打开文件的另外两种常用模式是什么？
    
      
    
- c. `open` 返回到 `fd` 中的是什么？它有什么用途？请在回答中兼顾成功和失败两种情况。
    
      
    

C

```
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char teststr[] = "The quick brown fox jumps over the lazy dog.\n";

main()
{
  int fd;
  int len;
  ssize_t r;

  fd = open("testfile", O_WRONLY | O_CREAT, 0600);
  if (fd < 0) {
    perror("File open failed");
    exit(1);
  }
  
  len = strlen(teststr);
  printf("Attempting to write %d bytes\n", len);
  
  r = write(fd, teststr, len);

  if (r < 0) {
    perror("File write failed");
    exit(1);
  }
  printf("Wrote %d bytes\n", (int) r);
  
  close(fd);
}
```

> **解答**：
> 
>   
> 
> - a. 代码将一个字符串写入文件。若文件不存在，则会创建新文件（`O_CREAT`）。
>     
>       
>     
> - b. 另外两种打开模式是只读（`O_RDONLY`）和读写（`O_RDWR`）。
>     
>       
>     
> - c. 失败时 `fd` 返回 `-1` 表示出错；成功时 `fd` 返回一个**文件描述符**（File Descriptor，一个非负整数），作为该打开文件的句柄，用于在后续的文件系统调用中标识所操作的目标文件。
>     
>       
>     

**7. 下列代码是上述代码的变体，执行了两次写入：**

  

  

- a. 两次写入后，文件的大小（字节数）是多少？
    
      
    
- b. `lseek()` 做了什么从而影响了最终的文件大小？
    
      
    
- c. 除了 `SEEK_SET`，还有哪些偏移量定位选项？
    
      
    

C

```
/* ...（代码同第 6 题，中间加入了 lseek 操作）... */
  off = lseek(fd, 5, SEEK_SET);
  if (off < 0) {
    perror("File lseek failed");
    exit(1);
  }

  r = write(fd, teststr, len);
/* ... */
```

> **解答**：
> 
>   
> 
> - a. **50 字节**。对于每个打开的文件，操作系统都会维护当前的文件偏移量（Offset），即下一次读写的起始位置。通常偏移量位于上一次读写结束的位置（两次 45 字节写入本来应为 90 字节），但受 `lseek` 影响改变了位置。
>     
>       
>     
> - b. `lseek` 将当前偏移量设置到特定位置。代码中的 `lseek` 将写完 45 字节后的偏移量重新移回到了距离文件开头 5 字节处；随后的第二次写入从第 5 字节开始覆盖写入 45 字节，因此最终文件大小为 5 + 45 = 50 字节。
>     
>       
>     
> - c. 还有 `SEEK_CUR`（基于当前位置偏移）和 `SEEK_END`（基于文件末尾偏移）。
>     
>

**9. 编译并运行以下代码：**

  

  

- a. 代码的作用是什么？
    
      
    
- b. 程序运行结束后，终端 Shell 的当前工作目录没有改变，为什么？
    
      
    
- c. `/bin/ls` 是在哪个目录下执行的？为什么？
    
      
    

C

```
#include <unistd.h>
#include <stdlib.h>
#include <stdio.h>
#include <errno.h>

main()
{
  int r;
  r = chdir("..");
  if (r < 0) {
    perror("Eek!");
    exit(1);
  }
  
  r = execl("/bin/ls", "/bin/ls", NULL);
  perror("Double eek!");
}
```

> **解答**：
> 
>   
> 
> - a. 代码将进程的当前工作目录切换为上一级父目录，然后执行 `ls` 列出该目录下的文件。
>     
>       
>     
> - b. Shell 会 `fork` 一个子进程来运行该程序。每个进程拥有独立的当前工作目录，因此该代码仅修改了子进程的工作目录，父进程（Shell）的工作目录保持不变。
>     
>       
>     
> - c. 在**子进程切换后的上一级目录**中执行。`exec` 只替换子进程的代码和数据内容，而不会替换子进程的运行环境；当前工作目录是由操作系统为每个进程维护的环境属性之一，因此 `ls` 会在子进程的当前工作目录下运行。
>     
>       
>

#### 三、进程与线程 (Processes and Threads)

**11. 在进程的三状态模型（Three-State Process Model）中，三种状态分别代表什么？各状态之间可能发生哪些状态转换？触发状态转换的事件是什么？**

  

  

> **解答**：
> 
>   
> 
> - **三种状态**：
>     
>       
>     - **运行态 (Running)**：进程当前正在 CPU 上执行。
>         
>           
>         
>     - **就绪态 (Ready)**：进程已准备好运行，但尚未被调度器（Dispatcher）选中分配 CPU。
>         
>           
>         
>     - **阻塞态 (Blocked)**：进程处于不可运行状态，正在等待某事件（如 I/O 完成）发生后才能继续执行。
>         
>           
>         
> - **可能的状态转换**：运行态 $\rightarrow$ 就绪态、就绪态 $\rightarrow$ 运行态、运行态 $\rightarrow$ 阻塞态、阻塞态 $\rightarrow$ 就绪态。
>     
>       
>     
> - **触发事件**：
>     
>       
>     - _运行态 $\rightarrow$ 就绪态_：时间片用尽、主动让出 CPU (`yield`)，或有更高优先级的进程进入就绪态。
>         
>           
>         
>     - _就绪态 $\rightarrow$ 运行态_：调度器选中该线程/进程作为下一个执行目标。
>         
>           
>         
>     - _运行态 $\rightarrow$ 阻塞态_：请求的资源（文件、磁盘块、打印机、互斥锁等）不可用，进程因等待资源而进入阻塞。
>         
>           
>         
>     - _阻塞态 $\rightarrow$ 就绪态_：所等待的资源变为可用，阻塞的进程恢复为就绪态以等待调度。
>         
>           
>         

**12. 在单处理器系统中共有 N 个线程：同一时刻最多可以有多少个线程处于运行态？多少个处于就绪态？多少个处于阻塞态？**

  

  

> **解答**：
> 
>   
> 
> - 运行态线程数 = **0 或 1**
>     
>       
>     
>       
>     
> - 阻塞态线程数 = **$N - \text{运行态数} - \text{就绪态数}$**
>     
>       
>     
>       
>     
> - 就绪态线程数 = **$N - \text{运行态数} - \text{阻塞态数}$**
>     
>       
>     
>       
>     

**13. 对比单线程文件服务器和多线程文件服务器的读文件性能：**

  

  

假设请求的数据块已在主存磁盘块缓存中时，服务器接收请求并完成处理需要 **15 ms**；有 $1/3$ 的请求需要进行磁盘 I/O 操作，这需要额外花费 **75 ms**（在此期间线程休眠挂起）。 分别计算单线程和多线程服务器每秒能处理的请求数（Requests/sec）。

  

> **解答**：
> 
>   
> 
> - **单线程服务器**：命中缓存耗时 15 ms，未命中耗时 90 ms (15 + 75)。加权平均耗时为：
>     
>       
>     
>     $$\frac{2}{3} \times 15\text{ ms} + \frac{1}{3} \times 90\text{ ms} = 10 + 30 = 40\text{ ms}$$
>     
>       
>     
>     每秒处理请求数 = $1000 / 40 =$ **25 个/秒**。
>     
>       
>     
> - **多线程服务器**：等待磁盘 I/O 的时间可以被多个线程并发重叠（Overlap），每个请求占用的 CPU 处理时间仅为 15 ms。 每秒处理请求数 = $1000 / 15 =$ **$66\frac{2}{3}$ 个/秒（约 66.67 个/秒）**。
>     
>       
>     

#### 四、临界区 (Critical sections)

**14. 以下只有一行代码，若被多个线程并发执行，为什么会发生竞态条件（Race Condition）？请举例说明 x 如何算错。**

  

  

C

```
x = x + 1;
```

> **解答**： 这行单句代码会被编译为多条机器指令：先将 `x` 对应的内存加载到寄存器中，执行递增操作，最后写回内存。 在线程 1 执行读取和写回之间的空档，线程 2 可能也完成了读取、递增和写回；当控制权切回线程 1 并写回时，线程 2 的修改就会被直接覆盖掉（或者线程 1 先读后增，线程 2 也先读后增，最后先后写回导致原本应加 2 的操作只加了 1）。
> 
>   

**15. 多线程并发调用以下函数，请找出需要互斥保护的临界区，并说明是否存在竞态条件：**

  

  

C

```
int i;

void foo()
{
    int j;

    /* random stuff */

    i = i + 1;
    j = j + 1;

    /* more random stuff */
}
```

> **解答**：
> 
>   
> 
> - 变量 `j` 是每个线程独立的局部变量，因此在 `j` 上**不存在竞态条件**。
>     
>       
>     
> - 变量 `i` 是跨线程共享的全局变量，因此 **`i = i + 1;` 构成临界区**，需要进行互斥保护（假设其余代码段不依赖于 `i`）。
>     
>       
>     

**16. 以下函数由多线程调用，在什么条件下会构成临界区？**

  

  

C

```
void inc_mem(int *iptr)
{
    *iptr = *iptr + 1;
}
```

> **解答**： `*iptr = *iptr + 1` 是否构成临界区取决于传入指针 `iptr` 所指向变量的作用域与性质：
> 
>   
> 
> - 若指针指向的是线程**局部变量**（如栈上分配的变量），则不存在竞态；
>     
>       
>     
> - 若指针指向的是**跨线程共享的全局或堆内存变量**，则存在竞态可能，此时该递增操作即构成临界区。
>     
>       
>
