
### 第一份讲义：`w04a2-files.pdf` —— 文件管理：程序员与用户视角

这份讲义从 **用户（User）和程序员（Programmer）的视角** 介绍文件系统的概念、接口抽象、目录命名与权限管理。

  

#### 1. 文件系统的演进与抽象

- **演进历史**：
    
      
    - **早期批处理系统（50年代）**：无操作系统与文件系统，通过穿孔卡片、磁带进行读写。
        
          
        
    - **第一代文件系统（60年代，如 PDP-8）**：单级目录（所有文件混在一个目录），文件必须连续存放且创建时需预知最大大小。
        
          
        
    - **MULTICS（70年代）**：引入多级目录结构（分用户隔离）、访问控制列表（ACL）和符号链接（Symbolic links）。
        
          
        
    - **UNIX**：继承 MULTICS 思想，简化了权限模型，并确立了经典的 **“一切皆文件（Everything is a file）”** 哲学。
        
          
        
- **文件系统抽象的对比**：
    
      
    - **用户视角**：统一命名空间、树状分层结构、任意大小的文件、符号化文件名、文件是一个逻辑对象、基于权限的访问控制。
        
          
        
    - **底层视角**：异构存储设备、扁平的块编号（Block numbers）、固定大小的物理块、文件块物理上可能碎片化离散分布。
        
          
        

#### 2. 文件命名、结构与类型

- **文件结构（File Structure）**：UNIX 和现代 OS 普遍将文件视为 **无结构的字节流（Sequence of Bytes）**，内核不强加内部结构，由应用程序（如 ELF 二进制解析器）自行解释。
    
      
    
- **文件类型**：普通文件（文本/二进制）、目录文件、设备文件（字符设备与块设备）、管道与流（Pipes/Streams）。
    
      
    
- **访问方式**：
    
      
    - **顺序访问（Sequential Access）**：从头到尾读写（磁带时代的遗留）。
        
          
        
    - **随机访问（Random Access）**：可跳转到任意偏移量读写（通过 `lseek` 移动文件指针）。
        
          
        

#### 3. 目录、路径与属性

- **目录树与路径**：
    
      
    - **绝对路径**：从根目录 `/` 开始的完整路径。
        
          
        
    - **当前工作目录（CWD）与相对路径**：使用 `.`（当前目录）和 `..`（父目录）简化路径引用。
        
          
        
    - **UNIX 命名优点**：格式统一规则、位置无关（Location independent，便于迁移和挂载）。
        
          
        
- **文件属性（Metadata）**：包含保护权限、所有者、创建/修改/访问时间（ctime, mtime, atime）、文件大小等。
    
      
    

#### 4. 共享、权限与并发控制

- **访问权限类别**：无权限（None）、知晓权（Knowledge）、执行权（Execution）、读取权（Reading）、追加权（Appending）、修改更新权（Updating）、更改权限权、删除权。
    
      
    
- **用户分类**：所有者（Owner）、所属组（Group）、所有人（All/Public）。
    
      
    
- **并发访问控制**：多进程同时读写可能产生竞态与死锁，OS 提供文件锁（如 `flock()`、`lockf()`），支持全文件锁定或特定字节区间（Record-level）锁定。
    
      
    

### 第二份讲义：`w04b2-vfs.pdf` —— 虚拟文件系统（VFS）、文件表与缓存

这份讲义进入操作系统内核层，讲解 **虚拟文件系统抽象（VFS）**、**文件描述符表的设计** 以及 **缓冲区缓存（Buffer Cache）与一致性**。

  

#### 1. 虚拟文件系统（VFS, Virtual File System）

- **产生背景**：早期系统只有一种文件系统；现代 OS 需要同时支持多种文件系统（ext2/3/4, FAT32, ISO9660, tmpfs, 网络文件系统 NFS 等）并在统一目录下无缝挂载。
    
      
    
- **核心思想**：将文件系统划分为 **与文件系统无关的通用代码层（FS-independent）** 和 **特定文件系统的驱动代码层（FS-dependent）**。
    
      
    
- **面向对象的设计模式（C语言实现）**：
    
      
    - **`struct fs` (VFS 级别)**：代表整个挂载的文件系统实例，包含全局操作的函数指针（如 `fs_sync`, `fs_getroot`, `fs_unmount` 等）及私有数据 `fs_data`。
        
          
        
    - **`struct vnode` (文件/inode 级别)**：内存中代表一个打开的文件对象的通用结构，包含引用计数、锁、所属 `fs` 指针、私有数据 `vn_data` 以及操作函数表 `vn_ops`（指向 `vop_read`, `vop_write`, `vop_lookup` 等具体文件系统的函数实现）。
        
          
        

#### 2. 三级文件结构设计演进（FD Table $\to$ Open File Table $\to$ Vnode）

讲义探讨了操作系统如何设计数据结构来管理打开的文件：

  

1. **方案一（只用 Vnode）**：若在 vnode 中存 offset（文件偏移量），则两个进程独立 open 相同文件时会冲突覆盖 offset。
    
      
    
2. **方案二（只用全局打开文件表）**：若系统仅有一张全局表且 fd 为下标，无法满足每个进程独立的 `fd 0, 1, 2`（stdin/stdout/stderr）需求。
    
      
    
3. **方案三（只用进程私有表）**：每个进程完全私有 offset，则无法支持 `fork()` 或 `dup2()` 规范中要求的“父子进程/复制描述符之间共享同一个文件读写偏移量”。
    
      
    
4. **最终方案（经典 UNIX 双层/三层表结构）**：
    
      
    - **进程级文件描述符表（Per-Process FD Table）**：每个进程独立，保存 `fd` 到打开文件表项的指针。
        
          
        
    - **系统级打开文件表（Global Open File Table）**：保存当前打开实例的 **文件偏移量（file offset）**、打开模式（read/write）以及指向对应 `vnode` 的指针。
        
          
        
    - **Vnode / Inode 表**：内存中唯一对应磁盘上的物理文件实体。
        
          
        
    - _效果_：既能实现独立 `open()` 各自拥有独立 offset，又能实现 `fork()`/`dup2()` 共享同一个 offset。
        
          
        

#### 3. 缓冲区缓存（Buffer Cache）与一致性

- **Buffer vs Cache**：
    
      
    - **Buffer（缓冲）**：解决传输速率不匹配和传输单位不一致（用户请求任意字节 vs 磁盘按块传输）。
        
          
        
    - **Cache（缓存）**：将访问过的磁盘块保留在内存中，加速后续重复读写。
        
          
        
- **优化策略**：
    
      
    - **预读（Read-Ahead）**：在顺序读取时提前将下一个磁盘块加载到内存。
        
          
        
    - **异步延迟写（Asynchronous Write）**：写入操作只需拷贝到内核 buffer 即刻返回，后台定期刷盘。
        
          
        
- **文件系统一致性（Consistency）权衡**：
    
      
    - **元数据（Metadata，如目录块、inode）**：一旦丢失会导致整个文件系统损毁，因此 **必须优先/同步立即写回磁盘（Immediate writeback）**。
        
          
        
    - **普通数据块（Data blocks）**：损坏仅影响单个文件，通常 **定期批量写回（Periodical writeback）**。
        
          
        
    - **直写模式（Write-through）**：修改立即写盘（如 DOS、U盘/可移动设备），虽然牺牲了 I/O 吞吐，但能防止拔出或掉电时数据损坏。
        
          
        

### 第三份讲义：`w04b-file-sys.pdf` —— 文件系统内部实现与磁盘布局

这份讲义聚焦于 **磁盘底层物理机制、文件在磁盘块上的分配策略、空闲空间管理以及目录底层存储**。

  

#### 1. 存储栈层次与局部性原理

- **存储栈自底向上**：物理磁盘（磁道、扇区） $\to$ 磁盘控制器（屏蔽坏道，暴露线性块 `0..N`） $\to$ 设备驱动 $\to$ 磁盘调度器 $\to$ Buffer Cache $\to$ 具体文件系统（FS） $\to$ VFS $\to$ 系统调用与应用。
    
      
    
- **物理局部性（Locality）的重要性**：
    
      
    - 机械硬盘的 **寻道时间（Seek time, ~15ms）** 和 **旋转延迟（Rotational delay, ~8ms）** 远远大于数据传输时间（4KB 仅需 ~10µs）。
        
          
        
    - 文件系统设计的核心原则之一是：**尽量把可能同时访问的块放在物理相邻或相近的位置**。
        
          
        

#### 2. 文件分配策略（File Allocation Methods）

如何将逻辑文件映射到物理磁盘块？

  

1. **连续分配（Contiguous Allocation，如 ISO 9660 光盘）**：
    
      
    - _做法_：文件占用一段连续的物理块，元数据仅需记录起始块号和长度。
        
          
        
    - _优缺点_：顺序读写性能极高；但创建时必须预估大小，且文件删除后会产生严重的 **外部碎片（External Fragmentation）**。
        
          
        
2. **动态链表分配（Linked List Allocation）**：
    
      
    - _做法_：每个物理块中保留几个字节存放指向下一个物理块的指针。
        
          
        
    - _优缺点_：无外部碎片；但 **随机访问性能极差**（需要遍历整条链），且数据块可能散落在磁盘各处。
        
          
        
3. **显式表分配（FAT, File Allocation Table）**：
    
      
    - _做法_：把所有链表指针集中抽取出来，在磁盘头部维护一张全局索引表（FAT），并常驻内存。
        
          
        
    - _优缺点_：随机访问加快（直接在内存表中跳步查找）；但 **大容量磁盘占用内存极大**（例如 200GB 磁盘可能需要 800MB 内存来加载 FAT 表）。
        
          
        
4. **索引节点分配（Inode-based，UNIX/Linux 经典结构）**：
    
      
    - _做法_：为每个文件配备一个独立的索引节点（i-node），里面记录该文件的数据块指针。只有打开文件时才将其 inode 加载进内存。
        
          
        
    - _多级间接寻址_：采用直接块指针（Direct blocks）+ 单重/双重/三重间接块指针（Indirect blocks），既保证了小文件访问极其迅速，又支持了极大文件的扩展。
        
          
        

#### 3. 空闲空间管理（Free-Space Management）

- **空闲块链表法（Linked List）**：利用未使用的空闲数据块自身来存放空闲块号指针链，完全不浪费额外的磁盘空间。
    
      
    
- **位图法（Bitmap / Bit Table）**：每一位（bit）代表一个块是空闲还是已占用。易于连续分配和就近分配（提升局部性），但大磁盘位图较大，可采用二级分层索引优化。
    
      
    

#### 4. 目录与属性存储实现

- **目录本质**：目录本身就是一个普通文件，其数据块中存放的是 **目录项（Directory Entries）** 列表，建立“文件名 $\to$ Inode 编号”的映射。
    
      
    
- **目录项格式**：
    
      
    - _定长目录项_：实现简单但浪费空间或限制文件名长度（如 DOS 8.3 格式）。
        
          
        
    - _变长目录项_：节省空间支持长文件名，但内部删除会产生碎片，需在内存中整理压缩。
        
          
        
- **属性存放位置**：
    
      
    - 直接存放在目录项中（如 FAT）。
        
          
        
    - 存放在独立的 Inode 中，目录项只存文件名和 Inode 编号（如 UNIX，便于硬链接 Hard Link 的实现）。
        
          
        

#### 5. 块大小权衡（Block Size Trade-off）

- **块越大**：元数据开销小，顺序 I/O 效率高；但 **内部碎片（Internal Fragmentation）** 浪费严重，且随机读小数据时加载了过多无用字节。
    
      
    
- **块越小**：内部碎片小；但元数据膨胀，大文件需要更多寻道与 I/O 传输次数。
