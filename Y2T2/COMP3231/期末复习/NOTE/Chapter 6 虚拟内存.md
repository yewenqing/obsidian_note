### 第一份讲义：w07b-tlb.pdf —— 分页机制、页表结构与 TLB

#### 1. 分页虚拟内存基础（Paging Basics）

- **分页与页框**：虚拟内存划分为等长的**页（Pages）**，物理内存划分为等长的**页框（Frames）**。
    
      
    
- **映射特性**：
    
      
    - 映射在运行时动态建立与修改。
        
          
        
    - 进程在物理内存中**不需要连续存放**。
        
          
        
    - 虚拟地址空间内部可以存在**未映射的空洞（Holes）**。
        
          
        
- **典型地址空间布局**：从高地址向低地址依次为操作系统内核段（Kernel）、向下增长的用户栈（Stack）、共享库（Shared Libraries）、向上增长的堆/数据段（Heap/BSS/Data）、只读的代码段（Text），以及保留未映射的第 0 页（用于捕获 NULL 指针异常）。
    
      
    
- **页面共享（Shared Pages）**：多个进程可以共享相同的物理只读代码段（Text），各自的页表将该区域映射到相同的物理 Frame，但数据段依然私有独立。
    
      
    

#### 2. 缺页异常与页表项属性（Page Faults & PTE）

- **缺页异常（Page Fault）**：访问未有效映射的虚拟页时触发硬件异常，交给操作系统处理：
    
      
    1. **非法地址（Illegal Address / 保护错误）**：向进程发送信号（Signal）或终止杀死进程。
        
          
        
    2. **页面不在物理内存中（Page Not Resident）**：分配空闲页框，从磁盘调入页面，更新页表，并**重新执行触发异常的指令**。
        
          
        
- **页表项（PTE）核心标志位**：
    
      
    - **Present/Absent bit（有效位/存在位）**：指示该页是否已建立有效物理映射。
        
          
        
    - **Protection bits（保护位）**：读（R）、写（W）、执行（X）权限控制。
        
          
        
    - **Modified / Dirty bit（脏位/修改位）**：标记该页在物理内存中是否被修改过（决定置换时是否需要刷盘）。
        
          
        
    - **Reference bit（引用位/访问位）**：指示该页近期是否被访问过。
        
          
        
    - **Caching bit（缓存控制位）**：指示 CPU 是否绕过 Cache 直接访问（如访问 MMIO 设备寄存器）。
        
          
        

#### 3. 应对大地址空间的多样化页表结构

在 32 位甚至 64 位系统中，单层平铺页表会占用海量物理内存，讲义对比了三大页表解决方案：

  

1. **多级页表（Multi-level Page Tables，如二级页表、Intel 4 级页表 PML4）**：
    
      
    - **原理**：将虚拟页号拆分为多级索引（如 10 位顶级索引 + 10 位二级索引 + 12 位页内偏移）。
        
          
        
    - **优势**：树状按需分配，**对于未映射的虚拟地址区域，其对应的下级页表完全不需要分配内存**（顶级条目设为 NULL 即可），大幅节省稀疏地址空间的内存开销。
        
          
        
2. **倒排页表（Inverted Page Table, IPT）**：
    
      
    - **原理**：不再以虚拟页号建表，而是**以物理页框（Frame）为索引**，每个物理页框对应一个条目，记录 `(PID, VPN)`。
        
          
        
    - **特点**：表的大小只取决于**实际物理内存（RAM）大小**，与虚拟地址空间大小无关。
        
          
        
    - **查找方式**：通过哈希锚点表（Hash Anchor Table, HAT）计算哈希值，顺着拉链（Chaining）匹配进程 PID 和 VPN。
        
          
        
    - **缺点**：难以高效支持不同进程共享同一个物理页框。
        
          
        
3. **哈希页表（Hashed Page Table, HPT）**：
    
      
    - **改进**：在 IPT 基础上，**将物理页框号（PFN）显式存储在表项中**。
        
          
        
    - **优势**：既保留了表大小随物理内存扩展的优点，又完美支持了多进程共享同一个物理页框。
        
          
        

#### 4. 快表（TLB, Translation Lookaside Buffer）与性能

- **TLB 的必要性**：多级页表每次访存都需要先访问多次内存读取页表，性能极低。TLB 作为 CPU 内部的高速全相联/组相联硬件缓存，缓存最近使用过的页表项。
    
      
    
- **TLB 加速效果**：若 TLB 命中率为 99%，平均内存访问次数由 2 次骤降为 $0.99 \times 1 + 0.01 \times 2 = 1.01$ 次。
    
      
    
- ==**硬件重填 vs 软件重填**：==
    
      
    - ==**硬件重填（Hardware-loaded）**：硬件 MMU 自动遍历多级页表并更新 TLB（如 x86, ARM）。==
        
          
        
    - ==**软件重填（Software-loaded）**：发生 TLB Miss 时触发硬件异常，由 OS 异常处理程序在软件中查表并写入 TLB（如 MIPS）。==
        
          
        
- ==**上下文切换与 Tagged TLB**：==
    
      
    - ==传统做法在进程切换时必须**完全清空（Flush）TLB**，开销很大。==
        
          
        
    - ==现代架构引入 **ASID（地址空间标识符）**，在 TLB 条目中附带 ASID 标签，切换进程时无需 Flush TLB。==
        
          
        

### 第二份讲义：w08a-tlb-replace.pdf —— TLB 重填与页面置换策略

#### 1. MIPS R3000 地址空间与 TLB 软件重填底层实现

- **MIPS R3000 虚拟地址空间划分**：
    
      
    - `kuseg` (0x00000000 - 0x7FFFFFFF, 2GB)：用户态和内核态均可访问，**必须经过 TLB 转换**，支持 Cache。
        
          
        
    - `kseg0` (0x80000000 - 0x9FFFFFFF, 512MB)：仅内核态访问，**不经过 TLB**（直接减去 0x80000000 得到物理地址），开启 Cache，常存放内核代码与数据。
        
          
        
    - `kseg1` (0xA0000000 - 0xBFFFFFFF, 512MB)：仅内核态访问，**不经过 TLB**（直接映射到底部 512MB 物理内存），**关闭 Cache**，专门用于访问 MMIO 外设寄存器和 Boot ROM。
        
          
        
    - `kseg2` (0xC0000000 - 0xFFFFFFFF, 1GB)：仅内核态访问，**经过 TLB 转换**。
        
          
        
- **专属重填异常向量（Special Exception Vector）**：
    
      
    - MIPS 为 `kuseg` 的 TLB Miss 专门设立了独立异常入口 `0x80000000`（与其他通用异常入口 `0x80000080` 物理隔离）。
        
          
        
    - **极速优化**：不需要判断异常类型，无需保存通用寄存器，仅使用保留寄存器 `$k0`, `$k1` 执行 8~9 条极简汇编即可完成页表读取并使用 `tlbwr` 写入 TLB。
        
          
        
- **OS/161 的简化教学实现**：OS/161 未启用多级页表前，遇到 TLB Miss 统一跳转通用处理函数压栈，64 个 TLB 项耗尽后会直接 Panic（仅支持 256KB 用户地址空间）。
    
      
    

#### 2. Amdahl 定律插曲（Intermezzo）

- **Amdahl 定律**：系统整体加速比受限于优化方案所占用的时间比例，核心设计哲学是 **“Make the common case fast（让高频常见场景极致快速）”** —— 这正是 MIPS 将 TLB 重填独立成专用极速向量的根本原因。
    
      
    

#### 3. 请求调页（Demand Paging）、局部性与系统抖动（Thrashing）

- **局部性原理（Principle of Locality）**：
    
      
    - **时间局部性（Temporal Locality）**：最近访问过的页面近期很可能被再次访问。
        
          
        
    - **空间局部性（Spatial Locality）**：访问某个地址时，其附近的地址很快也会被访问。
        
          
        
    - **90/10 规律**：程序 90% 的时间在运行 10% 的代码。
        
          
        
- **工作集（Working Set）**：进程在一段时间窗口 $\Delta$ 内所访问的全部页面集合，是进程局部性的近似度量。系统必须保证进程的 Working Set 常驻物理内存。
    
      
    
- **系统抖动（Thrashing）**：
    
      
    - **成因**：并发多道程序度过高，导致所有进程的 Working Set 大小总和超过物理 RAM 容量（$\sum \text{working set} > \text{total physical memory}$）。
        
          
        
    - **现象**：缺页率急剧上升，CPU 大部分时间都在等待磁盘换页 I/O，CPU 利用率骤降为接近 0。
        
          
        
    - **解决手段**：挂起（Suspend）部分进程并将其换出至磁盘，降低多道程序度，待内存压力缓解后再恢复。
        
          
        

#### 4. 虚拟内存管理策略（VM Policies）

- **页面大小（Page Size）权衡**：
    
      
    - **大页面**：减少页表大小、扩大 TLB 覆盖范围（降低 Miss 率）、提升磁盘连续传输吞吐；但会增加**内部碎片**、减弱对 Working Set 的精准适应能力、增大单次缺页延迟。
        
          
        
- **调入策略（Fetch Policy）**：
    
      
    - **请求调页（Demand Paging）**：发生缺页时才调入，避免浪费 I/O，但启动时缺页较多。
        
          
        
    - **预调页（Pre-paging）**：预测并提前批量加载，若预测错误会白白浪费 I/O 并可能误淘汰有用页面。
        
          
        

#### 5. 核心页面置换算法（Page Replacement Policies）

当物理内存满且发生缺页时，需挑选牺牲页（Victim Frame）淘汰到磁盘：

  

1. **最佳算法（Optimal, OPT）**：淘汰未来最长时间内不会被访问的页面；理论最优，但无法预知未来，仅作评估基准。
    
      
    
2. **先进先出（FIFO）**：淘汰最早调入内存的页面；实现简单但未考虑页面使用频率，性能最差。
    
      
    
3. **最近最少使用（LRU）**：淘汰过去最长时间未被访问的页面；效果最接近 Optimal，但要求硬件在每次访存时打时间戳，纯硬件实现开销过大。
    
      
    
4. **时钟置换算法（Clock / Second Chance）**：
    
      
    - **原理**：将所有页框组织为环形循环缓冲区，指针如同表针扫描；每个页维护一个引用位（Reference bit）。
        
          
        
    - **流程**：扫描时若引用位为 1，则将其置 0（给一次机会）并前进；若为 0，则直接选择该页淘汰并插入新页。
        
          
        
    - **软件模拟引用位**：对于没有硬件引用位的 CPU，操作系统可将 PTE 的 Valid 位置 0，通过捕获轻微缺页异常将软件引用位置 1 并恢复 Valid 位，从而以软件模拟实现 Clock 算法。
        
          
        

- **算法综合性能排行**：$\text{Optimal} > \text{LRU} > \text{Clock} > \text{FIFO}$。
    
      
    

#### 6. 驻留集分配与页面清洗策略

- **驻留集大小（Resident Set Size）**：
    
      
    - **固定分配（Fixed Allocation）**：每个进程固定页框数，易发生局部资源闲置或缺页频繁。
        
          
        
    - **可变分配 + 全局置换（Variable Allocation, Global Scope）**：维护全局空闲池，缺页时可抢占任意进程的页框，自动平衡系统负载（现代 OS 最常用）。
        
          
        
    - **缺页率方案（Page-Fault Frequency, PFF）**：动态监控缺页率，高于上限增加页框，低于下限回收页框。
        
          
        
- **页面清洗策略（Cleaning Policy）**：
    
      
    - **按需清洗（Demand Cleaning）**：选中淘汰且为 Dirty 时才写盘，缺页等待延迟高。
        
          
        
    - **预先清洗（Precleaning / Pagedaemon）**：后台守护进程定期批量将 Dirty 页面刷盘并清空脏位，使置换时能直接丢弃 Clean 页面，大幅降低换页延迟。
