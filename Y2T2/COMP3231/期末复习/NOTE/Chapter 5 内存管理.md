
讲义系统地展现了操作系统内存管理技术的演进脉络：从最早期的**单道程序/静态分配**，到**动态分区分配与基址/界限寄存器保护**，再到**交换（Swapping）**，最终引入现代的**虚拟内存分页机制（Paging & MMU）**。

  

### 一、 内存管理背景与单道程序设计（Monoprogramming）

1. **操作系统内存管理的核心职责**：
    
      
    - 记录和跟踪哪些内存正在使用、哪些处于空闲状态。
        
          
        
    - 在进程需要时为其分配空闲内存，并在释放时回收。
        
          
        
    - 管理 RAM 与外部存储（如磁盘）之间的数据交换。
        
          
        
    - 目标：最大化内存利用率和 CPU 利用率。
        
          
        
2. **单道程序设计（Monoprogramming）**：
    
      
    - 同一时刻内存中仅运行一个用户程序（早期批处理、简单嵌入式设备或 BIOS/Firmware 环境）。
        
          
        
    - **致命缺陷**：当用户程序等待 I/O 时，CPU 完全闲置，导致 CPU 利用率和内存利用率极低。
        
          
        

### 二、 静态分区分配（Fixed Partitioning）

为了实现多道程序设计（Multiprogramming），操作系统开始将内存划分为多个区域同时容纳多个进程：

  

1. **固定等长分区（Fixed Equal-sized Partitions）**：
    
      
    - 内存被划分为大小完全相同的固定分区。
        
          
        
    - **问题**：产生严重的**内部碎片（Internal Fragmentation）**（进程实际所需内存小于分区大小，分区内剩余空间被白白浪费）；且大于单分区大小的进程无法运行。
        
          
        
2. **固定不等长分区（Fixed Variable-sized Partitions）**：
    
      
    - 在系统启动时将内存划分为若干不同大小的固定分区（如 IBM OS/MFT）。
        
          
        
    - **多队列策略**：每个分区维护一个输入队列，作业放入能容纳它的最小分区队列中。_缺点_：大分区可能闲置，而小分区排长队。
        
          
        
    - **单队列策略**：所有作业排一个队，空闲时寻找能放下的作业。_缺点_：小作业被放进大分区，依然加剧内部碎片。
        
          
        

### 三、 动态分区分配与放置算法（Dynamic Partitioning）

根据进程实际需求按需分配连续的内存块（无内部碎片），但随着进程创建与销毁，会产生**外部碎片（External Fragmentation）**。

  

1. **碎片的定义对比**：
    
      
    - **内部碎片（Internal Fragmentation）**：已分配的分区/块内部未被使用的浪费空间。
        
          
        
    - **外部碎片（External Fragmentation）**：虽然系统总空闲内存满足要求，但由于它们被分割成不连续的微小片段（Holes），无法分配给新进程。
        
          
        
2. **空闲空间管理（链表法）与合并（Coalescing）**：
    
      
    - 操作系统将空闲内存按地址递增顺序组织为链表（Base, Size, Link）。
        
          
        
    - 进程终止时，系统会检查其相邻的上下邻居是否也是空闲块，若是则合并为一个更大的空闲块（Coalescing）。
        
          
        
3. **四大动态放置算法（Placement Algorithms）**：
    
      
    - **首次适应（First-fit）**：从头扫描链表，找到第一个足够大的空闲块；速度快，且能尽量保留内存高端的大块空闲空间，综合表现最好。
        
          
        
    - **下次适应（Next-fit）**：从上一次分配成功的位置继续往下找；直觉上想分散分配，但实际上打碎了高端的大空闲块，表现逊于 First-fit。
        
          
        
    - **最佳适应（Best-fit）**：遍历整条链表，找到与请求大小最接近的空闲块；需要完整遍历（浪费 CPU），且会留下大量极小的无用外部碎片。
        
          
        
    - **最差适应（Worst-fit）**：遍历整条链表，挑最大的空闲块进行切分；试图留下较大的剩余块，但搜索开销大且无法显著改善碎片。
        
          
        
4. **内存紧缩（Compaction）**：
    
      
    - 通过在内存中挪动/搬迁所有正在运行的进程，把分散的空闲碎片拼凑成一大块连续可用内存。
        
          
        
    - _代价与限制_：需要能够对运行中的程序进行动态重定位（Relocation），开销极大且必须依赖硬件支持。
        
          
        

### 四、 地址绑定与硬件支持（Base & Limit Registers）

1. **逻辑地址到物理地址的绑定时机**：
    
      
    - **编译/链接时（Compile/Link time）**：必须提前知道确切的物理运行地址，位置变动需重新编译。
        
          
        
    - **加载时（Load time）**：编译器生成可重定位代码，由加载器在装入内存时修改绝对地址。
        
          
        
    - **运行时（Run time）**：程序内使用逻辑地址，在每次 CPU 执行访问指令时由硬件动态转换为物理地址。
        
          
        
2. **基址与界限寄存器（Base and Limit / Bound Registers）**：
    
      
    - **重定位机制**：$\text{Physical Address} = \text{Logical Address} + \text{Base}$。
        
          
        
    - **保护机制**：硬件检查 $\text{Logical Address} < \text{Limit}$，若超出界限则触发硬件陷阱（Addressing error trap），防止越界侵占其他进程或内核内存。
        
          
        
    - **切换开销**：在进程加载、紧缩重定位以及进程上下文切换（Context switch）时必须更新这两个寄存器。
        
          
        
    - **局限性**：进程在物理内存中**必须占用连续的空间**，且无法实现多进程之间细粒度共享内存代码。
        
          
        

### 五、 交换技术（Swapping）

- **分时系统（Timesharing）需求**：进程数量增多且生命周期长短不一，物理内存不足以常驻所有进程。
    
      
    
- **机制**：当内存吃紧时，将低优先级或休眠的**整个进程**的内存镜像完整换出（Swap out）到后备存储器（Backing store / 磁盘），需要执行时再换入（Swap in）内存。
    
      
    
- **瓶颈**：由于涉及整进程内存的完整磁盘 I/O 读写，速度极慢（主要耗时在数据传输时间上）。
    
      
    

### 六、 现代虚拟内存与分页机制（Virtual Memory & Paging）

为了彻底解决“连续物理内存分配”与“整进程换入换出”的局限性，现代操作系统引入了**分页（Paging）**：

  

1. **分页基本概念**：
    
      
    - **页框（Frames）**：将**物理内存**划分为固定大小的块（如 4KB）。
        
          
        
    - **虚拟页（Pages）**：将进程的**虚拟地址空间**划分为与 Frame 大小完全相同的块。
        
          
        
    - **虚拟地址结构**：由虚拟页号（Page Number）**和**页内偏移量（Offset）组成。
        
          
        
2. **页表与地址映射（Page Table & MMU）**：
    
      
    - 操作系统为每个进程维护一张**页表（Page Table）**，记录虚拟页（Page）到物理页框（Frame）的映射关系。
        
          
        
    - **内存管理单元（MMU）**：CPU 发出虚拟地址给 MMU，MMU 查询页表将 Page 替换为 Frame，拼上 Offset 产生物理地址并送往内存总线。
        
          
        
    - 后续会结合 **TLB（快表）** 来加速页表转换过程。
        
          
        
3. **分页机制的核心优势**：
    
      
    - **无外部碎片**：分配以固定大小的 Frame 为单位。
        
          
        
    - **仅有微量内部碎片**：仅发生在进程最后一个页未填满时（向上取整）。
        
          
        
    - **物理内存非连续**：进程在物理内存中可以完全离散分布。
        
          
        
    - **便于内存共享**：多个进程的虚拟页可映射到同一个物理 Frame。
        
          
        
    - **细粒度交换**：支持按页（Page）为单位进行按需调度和换入换出。
        
          
        
    - **虚拟地址空间非连续（Virtual Regions）**：进程的代码段（Text）、堆（Heap）、栈（Stack）可以分布在虚拟地址空间的两端并动态增长，中间留空而无需分配实际物理页。
        

### 总结全景逻辑线

```
单道程序 (Monoprogramming，I/O阻塞CPU闲置)
  ↓
固定分区 (Fixed Partitioning，产生严重内部碎片)
  ↓
动态分区 (Dynamic Partitioning，First-fit等算法，产生外部碎片)
  ↓
基址与界限寄存器 (Base & Limit，支持运行时重定位与保护，但仍需连续内存)
  ↓
整进程交换 (Swapping，解决内存不足，但全量磁盘I/O太慢)
  ↓
虚拟内存与分页 (Paging + MMU，物理离散化、消除外部碎片、支持非连续虚拟段与按页调度)
```
