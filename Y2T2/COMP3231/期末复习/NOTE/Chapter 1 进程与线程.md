
### 第一份讲义：`w01a2.pdf` —— 进程与线程的概念与模型

这份讲义侧重于**高层抽象与核心概念**：

  

#### 1. 操作系统核心目标与进程模型

- **操作系统的基本目标**：交替执行多个进程（Interleaving）以最大化 CPU 利用率，同时保证合理的响应时间；负责分配资源，并支持进程间通信（IPC）与进程管理。
    
      
    
- **进程（Process）**：指运行中程序的内存映像，是**资源分配的单位**（拥有地址空间、打开的文件等），包含一个或多个线程。
    
      
    
- **线程（Thread）**：是**CPU调度的执行单元**（Execution unit），拥有自己的指令执行轨迹（Instruction trace），运行在进程的上下文中。
    
      
    
- **不同操作系统的模型**：
    
      
    - 单进程单线程：MS-DOS、简单嵌入式系统。
        
          
        
    - 单进程多线程：OS/161 初始分发状态。
        
          
        
    - 多进程单线程：传统 UNIX。
        
          
        
    - 多进程多线程：现代操作系统（Linux, Windows, macOS 等）。
        
          
        

#### 2. 进程生命周期与控制块（PCB）

- **创建与终止**：进程可由系统初始化（前台/后台守护进程 Daemon）、系统调用（如 `fork`）、用户请求或批处理作业创建；通过正常退出、错误退出、致命错误或被杀死而终止。
    
      
    
- **进程控制块（PCB）**：OS 用于管理进程的核心数据结构，包含寄存器状态、程序计数器（PC）、栈指针（SP）、内存段指针（Text/Data/Stack）、打开的文件描述符、用户ID等。
    
      
    

#### 3. 状态转换与调度队列

- **三状态模型**：
    
      
    - **Running（运行）** $\to$ **Ready（就绪）**：时间片用完（Timeout）或主动让出（Yield）。
        
          
        
    - **Running（运行）** $\to$ **Blocked（阻塞）**：等待 I/O、等待定时器或等待互斥锁/资源。
        
          
        
    - **Blocked（阻塞）** $\to$ **Ready（就绪）**：所等待的事件或资源就绪。
        
          
        
- **就绪队列与阻塞队列**：调度器（Scheduler/Dispatcher）从 Ready Queue 中选出下一个运行的进程；对于等待不同事件的阻塞进程，OS 通常维护多个独立的阻塞队列（Event Queues）以提高效率。
    
      
    

#### 4. 线程模型与并发模式比喻

- **进程级共享 vs 线程独占**：
    
      
    - **进程间共享**：地址空间、全局变量、打开的文件、子进程等。
        
          
        
    - **线程独占**：程序计数器（PC）、寄存器集合、栈（Stack）、运行状态。
        
          
        
- **汉堡店比喻（Hamburger Restaurant）**：
    
      
    - **单线程**：收银、炸薯条、煎肉饼全由一人按序做，遇到耗时等待（如等待肉饼烤好）就会完全阻塞后面的所有事。
        
          
        
    - **多线程**：多个员工（线程）并发处理不同步骤，一个等待 I/O 时其他员工继续干活，大大提升吞吐量和响应速度。
        
          
        
- **有限状态机（事件驱动模型） vs 线程**：事件驱动模型通过非阻塞调用显式管理状态，而多线程模型由 OS/运行时隐式在各自独立的栈上保存状态，编程模型更直观。
    
      
    

### 第二份讲义：`w03a-threads.pdf` —— 进程与线程的底层实现与上下文切换

这份讲义深入到**硬件架构（MIPS R3000）、汇编级函数调用规约以及上下文切换的真实实现**：

  

#### 1. MIPS R3000 硬件架构基础

- **Load/Store 架构**：算术/逻辑指令只能在寄存器之间进行（如 `add r3, r2, r1`），访问内存必须通过专用的 `lw`（读）和 `sw`（写）指令。
    
      
    
- **延迟槽（Delay Slots）**：
    
      
    - **Load Delay Slot**：`lw` 加载数据到寄存器后，下一条指令不能立即使用该寄存器（需隔一条指令或插入 `nop`）。
        
          
        
    - **Branch Delay Slot**：分支或跳转指令（`j`, `jal`, `jr`）紧随其后的那条指令**总会被执行**。
        
          
        
- **寄存器规约（Compiler Register Conventions）**：
    
      
    - `a0 - a3`：传递前 4 个参数。
        
          
        
    - `v0 - v1`：函数返回值。
        
          
        
    - `t0 - t9`：临时寄存器（Caller-saved，调用者负责保存）。
        
          
        
    - `s0 - s7, s8/fp`：保存寄存器（Callee-saved，被调用者必须保证返回时恢复原值）。
        
          
        
    - `sp` ($r29$)：栈指针。
        
          
        
    - `ra` ($r31$)：返回地址，由 `jal` 自动设置。
        
          
        

#### 2. 函数栈帧（Stack Frames）

- 函数调用时向下分配栈空间（`addiu sp, sp, -framesize`），保存调用者的 `ra`、`s8/fp` 和保存寄存器，并为局部变量和传参预留空间。
    
      
    
- 进程内存布局：包含代码段（Text）、数据/堆段（Data/Heap，向上增长）和用户栈段（Stack，向下增长）。多线程进程中，每个线程拥有独立的用户栈。
    
      
    

#### 3. 用户级线程（ULT） vs 内核级线程（KLT）

|**特性 / 维度**|**用户级线程 (User-Level Threads)**|**内核级线程 (Kernel-Level Threads)**|
|---|---|---|
|**管理位置**|用户空间运行库管理（TCB 在用户区）|内核管理（TCB 在内核区）|
|**切换开销**|极低（无需陷入内核 Trap/Syscall）|较高（进出内核需要上下文保存与开销）|
|**阻塞 I/O 影响**|**一阻全阻**：一个线程发起阻塞系统调用，整进程被挂起|**互不影响**：一个线程阻塞，内核调度该进程的其他就绪线程|
|**多核并行**|无法利用多 CPU（内核视其为单线程）|能真正并行运行在多核 CPU 上|
|**调度方式**|通常为协作式（Cooperative，需手动 yield）|抢占式调度（Preemptive，基于时钟中断）|

#### 4. 上下文切换（Context Switching）全过程详解

讲义以 OS/161 为例，图解并代码演示了内核线程切换的底层过程：

  

1. **陷入内核**：用户态发生中断/系统调用/异常，CPU 切换到该线程对应的**内核栈（Kernel Stack）**，压入 `trapframe`（保存用户态的 PC、SP 及所有通用寄存器）。
    
      
    
2. **内核 C 代码执行**：处理系统调用或中断处理函数（形成 C 调用栈）。
    
      
    
3. **调度决策**：内核决定切出当前线程，调用 `thread_switch()` 选取下一个就绪线程 `next`。
    
      
    
4. **底层汇编切换 (`switchframe_switch`)**：
    
      
    - 在当前线程内核栈分配空间，仅保存 **C 规约中的 callee-saved 寄存器**（`s0-s6, s8, gp, ra`），形成 `switchframe`。
        
          
        
    - 将当前栈指针 `sp` 保存到当前线程结构体（`cur->t_context`）。
        
          
        
    - 将 `sp` 指向目标线程保存的栈顶（`lw sp, 0(a1)`）—— **此时栈空间正式完成切换**！
        
          
        
    - 从目标线程的栈中恢复其 `s0-s6, s8, gp, ra`。
        
          
        
    - 执行 `j ra` 返回到目标线程之前离开 `switchframe_switch` 的位置。
        
          
        
5. **恢复用户态**：目标线程逐步返回，弹出 `trapframe` 恢复用户态寄存器与 PC/SP，回到用户空间继续执行。
