## 📄 第一份讲义：操作系统导论与结构 (w01a1.pdf)

这份讲义的主要目的是帮助你从**功能**和**结构**两个维度去理解操作系统（OS）。

### 1. 操作系统的两大核心角色

讲义通过“红绿灯”的例子说明：定义一个事物，既可以从它“扮演的角色”（功能），也可以从它“是什么”（结构）来看 。从功能上看，OS 有两个核心角色：

- **角色 1：抽象机器 / 扩展机器 (Abstract / Extended Machine)**
    
    - **核心逻辑**：底层的硬件（如 Haswell 架构平台）极其复杂，包含各种总线、寄存器和控制器 。如果让程序员直接去操作磁盘控制器的寄存器来写文件，那将是灾难性的 。
        
    - **OS 的作用**：它把复杂的硬件细节隐藏起来 ，向上层提供高级、易用的抽象 。例如，用**文件系统 (Filesystem)** 来代替裸磁盘的读写 。这使得程序不仅更容易编写 ，而且具备了**可移植性** 。
        
- **角色 2：资源管理器 (Resource Manager)**
    
    - **核心逻辑**：计算机的硬件资源（磁盘、内存、CPU、网络带宽等）是有限的，但通常会有多个用户或多个进程同时想要使用它们 。
        
    - **OS 的作用**：充当“公平的裁判”或分配者 ，根据特定策略（如先到先服务 FCFS、公平分享、配额限制等）给各进程分配资源 ，确保**系统高效利用** ，且**不会发生饥饿 (No Starvation)** 。
        

### 2. 操作系统的结构与特权级

从“实现结构”来看，操作系统是**运行在特权模式下的软件** 。

- **用户模式 (User Mode) vs 特权模式 (Privileged/Kernel Mode)**
    
    - **用户模式**：普通应用程序运行的地方，权限受限 。
        
    - **特权模式 / 内核态**：操作系统内核（Kernel）运行的地方，拥有最高硬件权限 。
        
    - **为什么要分权限？** 为了**隔离与安全** 。防止某个应用程序直接绕过操作系统去修改他人数据或破坏硬件 。
        
- **系统调用 (System Calls) 与系统库**
    
    - 应用程序如果需要用到硬件资源（如读写文件），必须跨越边界，通过**系统调用 (System Call)** 向内核发起请求 。
        
    - 讲义特别澄清：**系统库函数 $\neq$ 系统调用** 。像 `strcmp()`、`memcpy()` 纯粹在用户态做内存计算，不是系统调用 ；而 `open()`、`read()` 则是真正的系统调用 ；像 `malloc()`、`fprintf()` 则是**混合体 (Hybrids)**，只有在用户态缓冲区不够用时才会隐式触发系统调用 。
        

### 3. 操作系统的内部组织架构

讲义介绍了三种主流的内核设计结构：

- **分层架构 (Layered approach)**：最理想的理论模型，每层只依赖其内层 。但在现实中因为效率和复杂的相互依赖，**并不实用 (Unrealistic!)** 。
    
- **巨型内核 / 单体架构 (Monolithic Structure)**：又被称为“面条窝 (Spaghetti nest)”方法 。代码庞大，各个子系统（内存管理、进程调度、文件系统）虽然有一定模块化，但实际上紧密交织、互相调用 。**Linux 和 Windows 都是典型的单体内核** 。
    
- **无特权操作系统 (Privilege-less OS)**：一些嵌入式系统（如旧的 PalmOS、Mac OS 9、RTEMS）中没有硬件隔离，所有软件跑在一起，一个错误就能让整个系统崩溃 。
    

## 📄 第二份讲义：进程与线程 (w01a2.pdf)

操作系统的核心目标之一是在单台机器上“交错执行运行多个程序”，以最大化 CPU 利用率 。为了实现这一点，引入了进程和线程。

### 1. 进程 (Process) 概念

- **定义**：进程是一个独立运行的程序的**内存镜像 (Memory image)**，它是操作系统分配资源（如内存、打开的文件）的“所有者” 。
    
- **进程控制块 (PCB - Process Control Block)**：操作系统为了管理进程，在内核中为每个进程维护了一个数据结构（PCB），里面记录了进程的寄存器、程序计数器、内存段指针、文件描述符、用户ID等几乎所有信息 。所有 PCB 组合在一起构成了进程表 。
    
- **进程三状态模型**：
    
    1. **运行态 (Running)**：正在占用 CPU 执行指令 。
        
    2. **就绪态 (Ready)**：具备运行条件，等待被调度器选中 。
        
    3. **阻塞态 (Blocked)**：等待某个事件（如等待网络数据、文件输入、定时器响应）而无法继续运行 。
        
    
    - _状态转换触发事件_：从 Running $\rightarrow$ Blocked 是因为等待输入 ；从 Running $\rightarrow$ Ready 是因为时间片用完或主动放弃（Yield） 。
        

### 2. 线程 (Thread) 概念

- **定义**：线程是**执行的最小单位 (Unit of execution)** 。
    
- **进程与线程的关系（重点）**：
    
    - **进程是资源分配的单位，线程是 CPU 调度的单位** 。一个进程可以包含一或多个线程 。
        
    - **共享与私有**：同一个进程内的所有线程，**共享**该进程的地址空间、全局变量、打开的文件、子进程和信号 。但是，每个线程拥有自己私有的程序计数器（PC）、寄存器和独立的栈（Stack）来记录自己独特的方法执行轨迹 。
        

### 3. 经典的汉堡店类比 (The Hamburger Restaurant)

讲义用开汉堡店的例子生动地解释了**多线程** vs **多进程** vs **事件驱动（有限状态机）** 架构的区别 ：

1. **单线程汉堡店 (Single-Threaded)**：一个店员（单线程）。他点完单后，去炸薯条；在薯条炸好之前，他只能在油锅前傻等（**阻塞**），后面的顾客也只能排队等着 。**效率极低。**
    
2. **多线程汉堡店 (Multithreaded)**：汉堡店雇佣了多名员工（多个线程），他们共享同一个厨房（同一个进程的内存空间） 。有人负责接待，有人负责炸薯条，有人负责煎肉饼 。当薯条在炸的时候，炸薯条的员工可以被阻塞，但接待的员工依然可以服务下一位顾客 。这就是多线程通过**重叠 I/O 和计算**来提升总体性能的原理 。
    
3. **有限状态机 / 事件驱动模型 (Finite-State Machine / Event-based)**：店里依然只有一个人，但他绝不在任何地方死等（**所有操作非阻塞**） 。他通过“事件”来驱动工作：来了顾客（事件1） $\rightarrow$ 点单；薯条炸好闹钟响了（事件2） $\rightarrow$ 捞薯条 。
    
    - _对比_：多线程模型的状态隐式地保存在线程独立的栈（局部变量）上 ；而事件驱动模型的编程难度更大，需要程序员显式地在程序里维护和管理状态 。
        

### 4. 为什么要用线程？(总结)

讲义在最后总结了采用线程的几大核心优势 ：

- **易于编程**：相比于复杂的事件驱动状态机，多线程的同步逻辑更符合人类直觉 。
    
- **轻量省资源**：创建一个新线程比创建一个完整的进程要**便宜得多**（因为不需要复制整套内存和资源） 。
    
- **高效的数据共享**：线程间由于天然共享同一进程的内存，彼此通信和共享数据非常简单 （但这也带来了**并发控制/加锁**的挑战 ）。
    
- **充分利用多核多CPU**：在现代多核处理器上，多线程可以真正做到物理上的**并行计算** 。(注：如果所有线程都是纯计算密集型的，且在单核CPU上运行，多线程并不会带来性能提升 。)
